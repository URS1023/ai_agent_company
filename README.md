# 制造业 Agent 平台

面向设备质检、设备维护分析、产品批次质检。用户在同一平台完成取数、分析、人工复核、报表和AI操作。界面与业务后端正在统一，复用 Open WebUI、Dify、qKnow 和 Test5 的已有能力。

**当前已有可运行的前后端与真实业务闭环，整体仍在实施。** 原生运行、全部报表组件及完整需求验收见[共享进度](需求梳理/PROJECT_STATUS.md)。根目录 index.html 是历史样式原型，下面启动的是实际应用。

## 本机启动

**当前电脑直接双击根目录的 `启动系统.cmd`**，复用或启动 Windows 平台，打开唯一日常入口：

- 平台：<http://127.0.0.1:8080>，账号 `admin`。
- AI 对话、知识库、工作流和智能体均从平台菜单进入。
- 双击 `查看本机账号.cmd` 查看本机账号；双击 `停止系统.cmd` 关闭本项目服务。密码只保存在本机加密文件，Git 不包含账号密码或模型密钥。

**融合页面已经提供基础对话、知识检索和流程执行，完整原生功能仍在补齐。** 旧步骤流程支持知识检索、模型回答、文本整理；新图流程使用原 Graphon 内核执行分支、变量、迭代和循环，保存结构化输入输出、节点事件及同一请求的运行记录。13种已验证纯节点之外的完整图节点、工具循环、文件工作区等，以[实施验收表](项目文档/contracts/实施验收.csv)和[共享进度](需求梳理/PROJECT_STATUS.md)为准，不能用页面可打开代替功能验收。

原有 Open WebUI、Dify 和 WSL 沙箱部署保留，完整引擎需要时可显式执行 `deploy/native/desktop.py start`。日常入口启动平台及已配置的本机 Open WebUI，并在已配置专属WSL的电脑上保持纯图运行环境；纯图无需启动Dify整套业务服务。当前已实测复用平台、完整聊天和纯图环境，未改变现有14个原生角色；整机重启后启动尚未验收。日常页面仍只打开8080，不启动Docker。

其他电脑安装平台时，需要 Python 3.12—3.14、Node.js 22.12+；原生环境与本机加密配置需另行准备，见[部署说明](deploy/native/README.md)。下面命令仅启动平台：

```powershell
npm run setup
npm run build
npm start
```

访问 http://127.0.0.1:8080，首次自行创建管理员与工作区，无预置密码。开发运行 `npm run dev`，前端为 http://127.0.0.1:5173。

平台配置与任务保存在自己的 `.local/platform/platform.sqlite3`。本轮用户指定的本机 MySQL 数据库为 `szh_new`、`szh_new_food`；演示资料只导入独立 `aic_demo_*` 表，既有业务表及旧工作流绑定保留。配置项见 [.env.example](.env.example)，只读取当前进程明确设置的 AGENT_ 变量。原生服务准备见[本机部署](deploy/native/README.md)。

## 三个业务操作流程

| 任务 | 用户操作 | 实际结果 |
|---|---|---|
| 设备质检 | 创建设备/标准 → 导入或查询检测数据 → 映射指标 → 判定 → 复核 | 测值、缺值、单位、判定、标准版本和复核可回查 |
| 设备维护 | 选择设备与监测方案 → 分析 → 查看变化和证据 → 处理；也可自选历史查询 | 两期同工况变化、样本与覆盖率、来源和不足原因，不将统计变化当成确诊 |
| 产品质检 | 创建产品/批次 → 固定标准与样本计划 → 映射数值/成分/外观结果 → 判定/复核 | 批次、样本、原始证据和人工决定分别保存，数据不足不默认合格 |

质检运行可生成正式报告，保留当次标准、精确数值、样本明细与复核记录；支持HTML、PDF、Word、Excel、PPT、CSV、JSON。报告正文来源固定，修改规则后应重新检验，不能手工改写已保存的判定事实。

设备包包含九台合成设备的监测、事件、运行和维修记录；食品产品质检另有16个明确标记的合成样本，覆盖数值、成分、外观以及缺测/待复核分支。外观示意与已有检测结果供流程演示，不表示系统已训练视觉检测模型。导入、平台登记与三个业务验收工具分别位于 `tools/demo_data/`，收据保存在已忽略的 `.local/mysql-demo/`。导入需要可选依赖 `tools/demo_data/requirements.txt`；真实完成数量以收据为准。

**2026-10-21 本机演示已就绪：设备包 2,340,740 行和食品质检 16 个样本均已导入，并通过正式业务接口及实际浏览器验证。** `szh_new` 新增演示数据共 1,560,791 行，`szh_new_food` 设备包 779,949 行、产品质检 16 行；既有表与旧工作流绑定保留。

登录平台后，可直接打开以下已保存结果：

| 入口 | 打开的记录 | 可以演示什么 |
|---|---|---|
| 业务应用 → 设备质检 | 食品均质机01运行检验 | 6个样本的温度、振动测值、标准和判定 |
| 业务应用 → 预测性维护 | 食品均质机01同工况温度分析 | 1,860条观测、4个负载分组、同工况变化、证据与CSV下载 |
| 业务应用 → 产品质检 | 食品产品三维质检演示 | 16个样本的数值、成分和外观；4合格、6不合格、1待复核、5资料不完整 |
| 数据分析 → 报表设计 | 上述两份质检报告 | 查看对应检验结果的报告草稿；人工复核后再更新和发布 |

本轮维护案例的计算结果为正常，不能据此演示已预测故障或证明维修效果。质检任务及报告保留待复核/草稿状态；产品缺陷明细和包装示意图、维护CSV下载已在真实页面核验。页面操作读取已保存结果，不必再次导入数据包。

接企业数据库前核验实际主机、端口、库名、服务归属和授权范围。已有配置或回环地址不等于批准测试；超时后保留原收据，核查连接已停止后按明确授权恢复，不能直接重复运行导入脚本。

## 模型与密钥

指定 OpenCode Go 的 `deepseek-v4.1-flash`，向量为硅基流动 `BAAI/bge-m3`。密钥通过以下命令输入，输入不回显：

```powershell
.venv/Scripts/python.exe tools/configure_models.py
.venv/Scripts/python.exe tools/configure_models.py --check --probe
```

配置加密保存在 `.local/providers/`，原生启动只向所属子进程注入，不提交Git。每次显式probe各发一条短测试请求，不含业务数据、不重试、不切模型；本机部署和模型API接入分别配置。

## 修改与扩展

| 修改目标 | 主要入口 | 维护边界 |
|---|---|---|
| 菜单、页面、按钮权限 | apps/web/src/modules/manifest.ts 与对应模块 | 页面围绕任务，字段校验反馈规则 |
| 质检、维护算法 | services/platform/agent_platform/modules/manufacturing/ | 纯计算独立，标准/证据/复核保留历史 |
| 数据连接与SQL预算 | modules/data/connectors.py、sql_safety.py | 新适配器继续通过同一权限和预算层 |
| 报表组件和模板 | 后端 modules/reports/、前端 modules/reports/reused/ | 分别验收画布和导出，保留原类型语义 |
| 新平台模块 | agent_platform/registry.py 与前端 manifest | 独立router/service/model，声明权限 |
| 原生API/运行版本 | adapters/、modules/integrations/、deploy/native/ | 不重写聊天、节点或插件内核 |
| 数据表 | services/platform/migrations/ | 新建增量迁移，不改已发布历史迁移 |

编辑/删除携带revision；冲突返回409，引用资源先检查影响。配置目录复用仓储，质检、样本、查询和报表使用独立业务模型。

## 验证与数据库升级

```powershell
npm run check
npm test
npm run db:check
npm run db:upgrade
```

开发库首次启动可建表。已有未登记迁移版本的开发库，先停止写入并备份，再运行 `.venv/Scripts/python.exe tools/manage_database.py adopt`；结构不符会拒绝接管。生产启动禁止隐式建表，需明确迁移、独立 AGENT_MASTER_KEY 与HTTPS入口。

页面备份/恢复演练当前只操作平台自有SQLite，恢复到新文件，不替换运行库、不重放业务。文件目录、平台与模型主密钥、原生引擎数据库另行保管；单个平台数据库备份不等于完整灾备。
