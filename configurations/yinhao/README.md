# 银皓数据库业务工作流配置

本目录记录 2026-09-11 按“银皓数据库副本”重建的设备预警和质量检查工作流。数据库连接凭据、实测记录和旧流程备份不进入版本库。

## 页面入口和使用方法

- 设备预警：打开 `/alerts`，搜索设备，点击设备即可进入独立工作流页面。设备列表支持继续加载，避免只显示前 200 台。
- 质量检查：打开 `/quality`，在同一页面选择产品与模板。进场、过程、产品质检是分类，不另外创建三个业务模块。
- 修改取数：点击“读取值”节点，选择数据源、表、字段和筛选条件。选项显示数据库注释和原字段名。
- 多次取数：后续读取节点可选择上游关联字段，按设备、计划、任务、单据、项目等组合键关联。可保留全部匹配、按排序取最新一条，或要求唯一匹配。缺失记录保留为空，重复记录不会随意挑一条冒充唯一结果。
- 修改判断：在计算值和条件分支节点中修改字段、运算、比较方式和阈值；保存后测试，确认结果再发布。
- 质检试运行默认读取所选范围最新 100 张单据，可填写单号。需要扩大或改变范围时，在“产品质检单”读取节点中修改筛选、排序和取数数量；超出受控上限会报错，不会拿截断数据判定整批合格。
- 定时运行沿用平台现有任务配置。本次重建没有启用调度器，没有配置外发邮件或消息，也没有写回源数据库。

## 节点与判断来源

`device_graphs.py` 与 `quality_graphs.py` 生成普通可视化节点。`graph_builder.py` 负责连接与初始位置，不执行隐藏业务脚本。新业务图不依赖旧数据集、不调用旧子流程、不使用代码节点或手写 SQL。

设备巡检读取 `t_dinspectionmaintenanceplan`、`t_inspectiondevice`、`t_detailsofinspectionindicators` 中的范围、周期和项目要求。任务表 `t_deviceinspectionmaintenance` 同时包含已执行和提前生成的待执行任务；周期与实测分别取数，实测关联最近完成任务，避免直接使用未执行任务的空明细。区域/类型实际结果来自 `t_quyuleixingshebeibaoyangmingxi`，逐项实际结果来自 `t_deviceinspectiondetails`。

计划任务以计划名称关联而非计划主键，重名计划不能保证唯一归属，因此保留匹配数量并将不明确的时间判断标为待确认。小时、周周期与日历月周期分别计算，不把一个月固定当成 30 天。人工正常/异常记录按原文保留；没有独立数值时，不把要求中的数字作为实测值。

保养读取 `t_xunjianjihuarunhuabaoyang` 的润滑周期、油品、用量、方式、换油要求。保养任务及完成明细分别来自任务表和 `t_shebeirunhuabaoyangmingxibiao`。计划周期、润滑点周期、油品、方式、用量分别判断；一项缺数据不阻止其他项检查。kg/g 在有明确单位和数值范围时换算。未配置换油要求的点不额外产生换油问题；配置了换油要求但没有专门完成时间/实测用量时，不能用普通润滑日期替代。

维修读取 `t_equipmentmaintenancelog` 的任务、预计与实际完成时间、维修状态、验收和安装状态。失败、未完成超期、完成验收分别判断，记录缺失或状态不能识别时不判合格。

质量检查从 `t_qualityinspectiontemplate`、`t_qitemplatedetails`、`t_qualityinspectionproject` 读取产品模板和标准，从 `t_incomingmaterialqcform` 读取单据。实测来自普通逐项明细、统计明细及两张气体检测明细表，按原始项目编码对应字段。每行保留单据、模板、项目、原检验结果、当前标准、实测与源记录标识；单据汇总保留不合格项数和待确认项数。

比较规则采用源库的 `lte/gte/lt/gt/eq/ne/between_closed`。季节标准仅对源库明确给出的夏季 12%、冬季 14% 做共同范围检查，不能确定适用季节的中间区间待确认。原单据结论与当前标准复核结论分别呈现。

## 结果与连线

各检查输出直接进入“汇总全部检查结果”，没有输出节点串联。设备流程随后保存预警报告并结束；质检同时提供逐项结果和单据汇总。

箭头使用每条 SVG 连线路径自己的 `marker-end`，箭头标识与 edge ID 一一对应，颜色与路径相同。节点移动时路径端点重新计算，箭头随路径移动；缩放不改变连接关系。绿色表示该条边实际传递了数据，灰色分支不能因为汇总节点执行完成就被染绿。

## 数据边界

- 源库有记录不代表每个实测字段都已填写。例如区域明细中许多结果为空，保养执行明细很少；这些情况保留具体字段和记录依据，不伪造正常。
- 部分气体项目只有标准文件引用，未配置可执行的结构化阈值。当前流程展示实测和原结论，自动复核保留待确认。
- 未发现能直接执行的完整“让步接收”审批规则；本次不自动让步或放行。
- 所有计算使用当前服务器时间和实际数据库值。数据源仍是导入副本，不能把它当成持续更新的生产数据。

## 替换、验证与追溯

旧业务流程先备份，再创建、验证、发布新图，最后切换设备绑定及产品目录，并软删除旧设备预警/质检流程。保留旧版本和运行历史；通用工作流不在删除范围。

`inventory.json` 保存实际设备、产品范围与新工作流 ID。`verification.json` 保存验证摘要。完整旧定义、绑定备份、源库快照和实际运行证据保存在本机 `.implementation/business-rebuild-20260911/`，该目录不推送。
