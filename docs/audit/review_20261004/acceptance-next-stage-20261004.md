## 真实验收入口的本次只读检查

只读取现有脚本，没有导入执行、读取凭据、启动服务、连接数据库或请求模型：

- `tests/dsh/live_business_acceptance.py` 已能核对独立设备保养基准、实际Office字节和跨轮PPT修改，但它使用HTTP接口而非浏览器；不能把运行此脚本记成浏览器验收。该入口目前显式调用 `LiveModelProxy.from_opencode(..., model="deepseek-v4.1-flash")`，不能原样拿来执行已授权的Agnes业务数据测试。
- `tests/dsh/live_inventory_acceptance.py` 保留库存逐字段、NULL、单位与重复行验证，以及数据库审计计数；复用前须检查当前源码和授权目标，不从历史基准直接推断今日数据库状态。
- `tests/dsh/live_model_proxy.py` 有固定上游、有限请求数、无重定向与无自动重试，以及只记录指标的代理；支持显式 `from_env`，但模型和目的地必须在执行前按本次授权核对。默认模型名字或用户机器上的其它工具配置不能代替授权。
- `tests/dsh/live_baseline.py` 有本机MySQL服务归属核验、固定四表元数据、单设备基准、单业务SELECT、3秒查询边界及数据库异常STOP记录。它的基准只表达保养计划要求，不能据此回答实际已巡、未巡或逾期数量。

## 下一步执行顺序与限额

1. 先完成当前固定源码整合门禁和完整浏览器单轮，保留每个原始失败；不在旧运行未终止时重复启动同一验收。
2. 完善独立真实验收入口：显式选择已授权的Agnes目的地与模型，校验host/HTTPS/固定路径，凭据只在内存读取；业务数据发送沿用用户对本次1000条验收的Agnes授权，不自动转发到其它模型服务。若配额不足，免费模型可先用合成问题核验；模型可用性与费用属性须有当前证据，不能把未验证档位称为免费。
3. 每次真实数据库执行前重新核验 `127.0.0.1:3306/szh_new` 的物理服务归属和现有停止记录；只建临时平台，不迁移在用平台或改变工作流绑定。首个样例分两个串行阶段：独立基准1条业务SELECT，Agent查询1条业务SELECT，**总计最多2条业务SELECT、两次测试连接、查询并发1、每条3秒**；每次执行前检查计划，身份、元数据、EXPLAIN及会话控制语句另计并限定总额。不能把基准查询隐藏在“只查1次”的统计外。模型提出的SQL必须先受同一表/字段/只读/工作量限制，不能让agent循环或重启子进程绕过本轮总预算。
4. 从一个明确口径的设备或库存问题开始，保存独立预期、模型SQL、实际结果、终态、工具次数及导出文件内容。NULL、重复行、计划与执行、单位不得被“好结果”措辞掩盖。数据库一旦超时、断连或资源异常，立即停止并核实原查询，按用户约束处理，不能扩大时限或自动换库重试。
5. 将通过的小样本接到实际浏览器输入、选择数据范围/模型、查看结果、下载和继续使用流程。随后按COV清单扩展页面与异常路径；完整宽度单轮通过后，再制定分批百轮与24小时连续运行记录。当前完整浏览器runner每套都会启动、关闭临时Host，累计运行时长不能证明单一服务连续运行24小时；后者须独立保留同一服务身份、启动时间、健康状态与期间故障记录。

所有未来动作均为待实施计划。本文没有增加任何真实查询或模型调用，也不增加已完成用例数；当前8011在用服务加载仍未确认。

设计复核补充：当前DSH由Agent读取schema后以SQL模式调用业务查询工具，工具不接受旧natural_language模式；真实验收应记录实际SQL工具参数及持久查询结果，不能沿用旧入口只检查generatedSql和一个设备名称的弱断言。现有live_python_guard默认是进程内6次SELECT/12次连接/120条命令，不能作为上述跨进程总预算的证明；执行新样例前须补齐本轮共享计数和最小已验证schema。当前业务schema工具已经是cached_only且不采样，不能误报它自动连库；新入口仍须禁止管理sync、profile聚合及其它额外取数路径绕过样例预算。

凭据边界：真实Agnes密钥只交给父进程内的固定目的地代理，临时Host与浏览器只使用本机代理的占位密钥；现有MySQL源注册会将本机口令加密保存在临时SQLite平台，不能声称全部凭据都只在内存。临时数据目录须按所有者回收，原始明文不进入日志、页面或模型请求。
