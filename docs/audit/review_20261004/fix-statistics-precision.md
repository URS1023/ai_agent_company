# 批次十三：统计精度与下一观测点预测

基线：`112bdd3`。关联原审查：`followup-analytics.md` 的 ANA-N04、ANA-N07。本次只修改 `backend/app/modules/analytics/statistics.py` 及新增专项测试，不连接业务数据库、不调用模型。

## 复现与修复

- 原预测在中心化拟合后忘记减去横坐标平均值。连续四期 `1、2、3、4` 的下一点得到 `6.5`，下降序列得到 `-1.5`；现在与拟合线使用相同坐标，分别得到 `5` 和 `0`。预测仍仅代表按返回观测序号的一步线性外推，不是正式业务预测。
- Decimal 从字符串构造虽然保留原始值，但默认 28 位上下文仍会在求和、均值、中位数、趋势和离群计算时舍入。原 30 位正负数抵消再加 `0.1` 得到 `10.1`；现在按输入整数/小数跨度及行数预留局部精度，合计保持精确。
- `normalize()` 不是纯文本格式化；它按上下文舍入。替换为不参与运算的格式化，保留整数末尾的零，只去除小数末尾的零。
- 每列暴露 `arithmetic` 口径：精度与 `ROUND_HALF_EVEN` 除法舍入。循环小数、回归不能宣称无限精度；上下文不受调用者的低精度、不同舍入或 Inexact trap 影响，也不污染调用者设置。
- 极端指数或异常超长值超过 4096 位计算预算时保留原始明细，明确标记 `decimal_precision_budget` 并生成质量提示；不偷偷给出舍入合计，不展开十亿位字符串。此预算远高于常规 MySQL DECIMAL 位宽，不改变查询时限。
