- `apps/analytics/src/utils/snapshotChartOption.js:8` 把精确文本转成 Number，`:52` 使用 ECharts 默认 tooltip；系列只保存近似值，没有精确原值并列通道。绘图坐标使用浮点本身可以接受，但提示内容不能据此冒充精确查询值。
- `utils/dashboardData.js:67` 的 numericValue 也返回 Number，normalizeSeriesRows 和 inferSeriesSchema 均提前丢弃数值原文；`aiChartOption.js` 和 `JimuChart.vue` 的普通、仪表和雷达路径继续复用这些数据。

- SmartChart 的 isNumericColumn 仅用 `!isNaN(Number(v))` 判断，空白、布尔和非有限数边界与 dashboardData.numericValue 不一致。精确数值文本修复不能顺便把这些值冒充有效数量。

## 最小实施方向

保留查询原值与绘图近似值两个字段；tooltip/明细使用精确文本格式化器，坐标和尺寸用经过有限值校验的近似值。不要把序列整体换成字符串后假定 ECharts 内部仍保留文本；按真实图表渲染及 tooltip 内容验收。需要计算的新总和采用受控十进制运算或者可信后端聚合，明确缺值和有效计数，不能用约值冒充精确总计。

分类桶使用 Map 或明确无原型字典，并按键是否存在判断；同时保留空类别、0 值、类别顺序和既有权限内数据范围。缺失数值保持未知，不能任意补零。tooltip 若使用 HTML 必须转义业务类别和字段注释；优先受控文本渲染。

复用批次十三的 `utils/decimalDisplay.ts` 仅能解决原文展示，不具备十进制求和功能，不能因此宣称聚合精度已经处理。

2. 同类大数抵消：SmartChart 对同一类别求和 `9007199254740993` 与 `-9007199254740992`，期望精确和为 1；再加小数和缺失值，检查柱/饼两路一致，不能只测新纯函数而跳过组件集成。
