# 2026-09-28 AI 对话、业务数据与交付续测

本轮在已有 DSH 宿主与业务插件实现上继续测试和修复。目标是同一任务多轮处理、内部库存查询准确性、独立文件交付以及取消／重启后的状态一致性；保持现有页面外壳。本文只记录实际覆盖的功能，不将结果推广到系统全部接口或任意长度的任务。

## 已复现并修复的问题

- **下一轮导出被拒。** DSH 每轮生成新运行 ID，旧导出验证只接受本轮或旧引擎恢复字段。现在同一稳定任务、同身份、同会话和同数据范围可以复用已结束轮次的成功查询；改变文件名、标题或模板无需重查。范围变化仍重新核对。
- **第二份内容型 PPT 复用第一份草稿。** 原来一个任务只有一份活动草稿。现在每个标题拥有独立草稿 ID，写页和最终生成均可指定该 ID；支持交错写入、跨轮修改第一份、旧单稿迁移与删除后重新创建。
- **库存复合关联产生重复行和错误名称。** 原语义同步将复合外键拆成单列，组织不同但物料编码相同时会串关联。现在完整保留并使用全部关联字段，修复旧缓存和反向关系标记；缺少任一必要字段时不提供残缺关联。
- **过期元数据与不完整字典被描述为可用。** 数据源版本改变后，旧结构保持过期状态，不返回自动可用；目录枚举超过摘要上限时明确标记截断和不完整。
- **元数据读取失败后继续查询。** 行数统计只在明确权限不足时降级，超时或断连立即停止，不执行后续结构查询。
- **单位“一致”的范围不清。** 原统计指逐条对照库存与物料的单位，模型可能理解为所有记录使用相同单位。保留原字段并补充比较范围、按单位的记录条数分布，以及未知单位独立计数。
- **概况回答把物料目录误解为无库存物料。** 真实短测发现模型附带查询仓库与物料目录，并做出缺乏关联核验的无库存推断。现在纯库存概况／单位／预警回答由当前轮的成功库存回执核对，重新计算本页事实并替换最终正文；明确咨询、明细、历史、定制查询和文件任务不接管。失败不借用历史查询，不将多页结果擅自合成一页。提示与业务 Skill 同时约束无需额外查询目录。
- **队列编辑与取消竞争。** 取消后到达的旧编辑回执不能恢复排队状态；同任务并发编辑返回明确冲突，避免提前解除执行锁。
- **恢复旧运行误用最新运行状态。** 宿主重启后按目标运行 ID 恢复 SSE 终态；前端移除排队项不清空另一条活动任务进度，丢失回执恢复也读取该轮实际状态。

## 实际模型两轮交付

使用真实 OpenCode `deepseek-v4.1-flash`、原生 DSH 宿主和 Python Worker。平台状态使用临时 SQLite，业务只访问本机原生 MySQL80 的 `127.0.0.1:3306/szh_new`。已再次核对监听进程与服务归属；每条业务查询先核验执行计划，有查询期限和次数预算，没有连接其他数据源。

本轮重新读取独立 SQL 基准：4 条库存、每条 16 个原始字段，以及 43 项单位选项。Excel、库存接口和查询历史均与基准逐字段核对，保留原始 NULL。

这些是有限场景实测，不能当作所有任务的时限承诺或总体准确率。模型调用仍是文件制作的主要耗时来源；本轮没有做并发压力测试，也没有修改业务库数据、索引或在用工作流绑定。

## 短对话的准确性复验

原问题为“查看当前仓库的备品备件库存，简短说明有哪些计量单位、单位是否一致，以及库存预警结论。无需生成文件。”

第一轮 23.172 秒，单位口径已正确，但人工检查发现额外的目录查询和无库存推断，因此未将它视为最终准确性验收。补上本轮库存证据核对、严格的适用范围及避免附带查询的提示后，最后复验为 **16.250 秒，1 次库存 SELECT，0 次目录查询**，全部四项断言通过。最终正文为：

> 已读取库存的本页快照：4 条库存记录，涉及 3 种物料。本页记录数不作为全库总量。
>
> 计量单位：桶 2 条、根 2 条。逐条核对同一记录的库存单位与物料单位：一致 4 条。这不表示不同记录的单位相同；不同物料或不同单位的库存数量不可合计。
>
> 库存预警：4 条为未知（4 条缺少安全库存阈值）。不能据此判定库存正常或直接形成补货结论。

隔离回归同时验证最终事件与刷新后的历史正文一致，流式输出中的错误文本会被正式结算结果替换。该功能只对已测试的简单库存概况生效，不代表自由问答具有确定性准确率。
