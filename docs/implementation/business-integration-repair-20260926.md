# AI 对话、内部业务接口与数据链路修复验收

本次针对用户截图中的设备预警、备件库存和多文件交付链路实施修复，保留原有页面外壳。代码、平台已同步元数据和实际默认模型一起修正；业务库记录、索引和在用工作流绑定没有修改。

## 已实现的业务链路

```text
DSH 对话／业务页面
  ├─ 预警服务 → 独立报告页／问题页 → 同范围 Excel
  ├─ 库存／仓库／物料固定查询 → QueryHistory/queryId
  │                              ├─ 原始值 Excel
  │                              ├─ 完整数据 PPT
  │                              └─ 图表／大屏
  ├─ 已保存 HTTP 来源 → 一次固定接口请求 → 同一查询结果链路
  └─ 通用内容 PPT → 大纲／分批正文／最终文件
```

- `POST /api/v1/analytics/inventory/query` 与 `query_inventory_data` 使用同一服务。`kind` 区分 `inventory`、`warehouses`、`materials`；筛选支持仓库、物料、名称、批次以及分页。不适用于当前类型的筛选明确拒绝，不能静默丢条件。
- 标准库存查询只执行一次确定性 SQL，不再调用模型转 SQL。必须已有有效版本的元数据；没有快照时提示同步，不能为一次库存查询临时扫描全库。
- 关联只来自真实外键或已同步的低代码声明。仓库、物料、仓位使用业务主键关联，不能误把自增 `autoId` 当业务 ID。已删除或缺失引用不会让库存行消失。
- 单位编码与字典标签分开保留；坏字典、歧义代码和空标签显示未知。空安全库存不是零，也不能用物料级阈值判断某一批次正常。不同物料或单位不合计成“库存总量”。
- 导出 Excel、数据 PPT、图表和大屏都接收同一成功查询的 `queryId`，保持身份、来源、字段、空值和截断范围。Excel 在创建时确定中文文件名，消除把工件 ID 当文件 ID 再改名的失败。
- 数据 PPT 按真实行列分页，宽表保留原始行号，长文本的完整值写入同页备注。内容型 ERP 介绍仍使用演示插件；中文“六到八页”等明确对象约束按包含封面／结尾的物理总页数执行。
- 预警报告与问题分别返回分页信息和关联范围；纯预警最终答复由本轮证据核对，不能把待处理写成已解决。复合文件任务保留完整正文。
- 目录发现与 schema 查询只使用平台缓存，不隐式连接业务库或调用 embedding。字段裁剪优先保留业务键、名称、单位、状态及关联键，并明确裁剪范围。
- 重新同步时，低代码引用使用唯一已核实业务键补齐关联，结构快照与语义目录一致持久化；旧主从声明继续用于表级召回，但不捏造 JOIN 键。实际元数据读取失败立即停止，不再换 SQL 重试。
- 工具执行过程在前端折叠成一条；失败数量与原始回执仍可展开。交付文件集中显示，去除已匹配文件卡片的重复下载表，真实耗时来自服务器起止事件。
- DSH 大结果保存完整原值，支持按 JSON 字段读取。小集合在摘要预算内直接返回所有项并标记 `complete=true`，消除四行库存仍反复分页读取的等待。
- 业务查询回执和当前时间工具明确本地时区偏移，同时保留 UTC 时间，避免夜间任务把 UTC 日期误报为本地昨天。

## 本机数据核验与平台应用

实际目标为本机原生 MySQL80 的 `127.0.0.1:3306/szh_new`。核对监听进程、服务父子进程、主机与数据目录，确认不是代理或隧道。局域网与其他已保存数据源没有连接。

只读取四张业务表的一页独立基准：`t_spinventory`、`t_sparepartsinfor`、`t_basicinformationofthewarehouse`、`t_warehouselocationinformation`。先检查 EXPLAIN，再执行带两秒限制的 SELECT；计划为库存 4 行、物料索引点查、仓库 7 行、仓位索引点查。元表及单位选项另外有限读取，每条先 EXPLAIN 并记录次数。

核对结果：4 条库存、3 种物料；仓库名称和“桶／根”单位标签能够通过已有记录解析。4 条安全库存为空，3 条批次为空，仓位字段为空。这些缺项保留为未知，没有自动编造业务值。

对当前平台所选的本机 `szh_new` 来源补入四表已核实的业务主键、名称、关系和单位字典，保留全部 435 张原授权表。平台元数据变更有本地备份及审计；没有改变数据源版本、授权范围或任何工作流绑定。

OpenCode 实际模型目录确认存在 `deepseek-v4.1-flash`。将 `reasoning`、`opencode_go` 两个现有角色的模型 ID 改为用户指定的这一模型，保留原端点、密钥和其他配置。

## 实际模型与接口结果

使用真实 DSH 宿主和 OpenCode `deepseek-v4.1-flash`，平台数据隔离到临时 SQLite，仅业务 SELECT 指向已核实的本机库。宿主中的数据库保护限制串行查询、表范围、3 秒查询期限、最多 6 次业务 SELECT；每次先 EXPLAIN，异常立即停止。

| 核验项 | 实测结果 |
| --- | --- |
| 库存 HTTP 接口首次请求 | 312 ms，包含 HTTP、权限、持久化和查询 |
| 仓库目录 HTTP 接口 | 125 ms，返回 5 条 |
| 物料目录 HTTP 接口 | 156 ms，返回本页 20 条，不视作全库总数 |
| 查询历史读取 | 32 ms，原值与本轮结果相同 |
| 最终复合任务 | 42.437 s，库存查询＋Excel＋库存数据 PPT＋ERP 介绍 PPT |
| 首个模型输出 | 3.171 s |
| 模型调用 | 6 次，总网络时间 38.702 s，0 次错误 |
| 最终任务业务 SELECT | 1 次，含 EXPLAIN 的驱动测量 15 ms |
| 工具结果分页读取 | 0 次 |
| 实际交付 | 1 个 XLSX、6 页数据 PPT、8 页 ERP PPT |
| 原始值比较 | 4 行 × 16 个原始字段＝64 项与独立 SQL 一致；Excel 同样逐项一致 |

第一轮任务 52.578 秒，数据及文件生成通过，但暴露 ERP 要求 6–8 页实际输出 9 页的问题。已将该轮最终验收标为失败，保留测量结果；补齐总页数约束和小结果内联后，第二轮 42.437 秒通过全部断言。

两轮合计：真实接口／模型验收共 2 个业务连接、5 次业务 SELECT、60 条驱动命令，0 次查询失败；独立 SQL 基准另有 1 个连接、1 次业务 SELECT。元数据取证连接和平台本地配置读写另行记录，没有并发压测或修改业务行。

用户截图旧任务为 333 秒、4 个文件、40 次工具调用，其中 22 次 `read_tool_result`。最终新样例为 3 个文件，内容和模型不同，不能据此声称严格同任务提速比例。当前剩余主要耗时在模型内容生成，不能保证任何复杂任务都在 42 秒内完成。
