# AI 复合交付的通用质量校验与回归入口

目标是后续任务稳定生成可核对、可阅读的交付。以下规则进入正常生成和验收路径，不依赖特定会话、查询标识或某一张模板。文末的历史修复只是问题复现与兼容验收样本。

## 每次生成都会执行的检查

- 大屏生成先计算必需展示字段，再按组件类型、实际可用面积和表格列容量分配。所有已识别业务数值字段（包括声明为数值但全为 NULL 的字段）默认纳入；显式选择指标时按选择范围检查，不擅自扩展。
- 保存前必须完成必需字段覆盖；窄表不能凭保存了完整原始数据就声称完整展示。无模板模式自动选择单栏、双栏和保留识别字段的分组表格。超过可读容量或复制预算时返回可修正的错误，不保存为成功交付。
- 完成任务时再检查实际组件及投影，隐藏组件、画布外组件、数值映射错误、图表未使用的表格列、文字组件携带的假绑定，不能贡献已展示字段。
- 财务 PPT 和大屏共用保存查询的财务证据；标题声称“应收应付”但查询只证明应付时，自动标记应收未验证并写入范围说明。缺失不当成零，也不据此判断整个数据库不存在该业务。
- 查询 PPT 默认使用汇报模式，明细预览与完整数据备注分开。实际文件的页数、可见数值、表格、原生图表和完整来源备注逐项核对，通过后才登记工件。模型漏填范围说明也会自动补入正文。
- 复合任务保留每份交付要求；对已列出选项的澄清回复沿用未完成任务。两份不同用途 PPT 分别计数和验收。中英文流程咨询、拒绝与明确制作分别处理；逗号后的纯产物枚举可继承制作动作，否定句不会传递制作意图。
- 快照组件按设计画布与槽位适配字号、图内边距和表格，保留真实值和完整编码提示；图表使用 SVG。未知数据保持缺失状态。
