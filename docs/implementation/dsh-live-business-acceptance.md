# DSH 真实业务与模型验收

日期：2026-09-26。本记录追加到首次 DSH 重构的隔离验收之后，区分真实数据库、真实模型与模型桩；原始业务行、生成文件和事件日志只保留在本机 `.implementation/live_dsh_acceptance/20260926-opencode/`，不进入版本库。

最终量化结果见 [脱敏验收汇总](dsh-live-business-results.json)。下方同时保留修复前失败，不能只用末次成功覆盖问题记录。

## 环境和范围

- 真实数据库：本机 `127.0.0.1:3306/szh_new`，MySQL 8.0.46；端口实际归属本机 MySQL80 / mysqld.exe，已核验父子进程与数据目录。
- 真实模型：OpenCode Go，实际请求和上游响应均为 `deepseek-v4.1-flash`；使用本机 OpenCode 配置中的接入凭据，凭据不写入报告。关闭思考，验收配置为 32,768 上下文、4,096 单次输出。
- 实际运行：当前 Node DSH 宿主、Python stdio 业务 Worker 和真实 HTTP 接口。平台台账使用独立临时 SQLite；业务查询只到上述本机 MySQL。验收时常用部署端口没有运行服务，因此不是在用部署的验收。
- 数据样本：单个设备的四表润滑保养要求查询，最多 10 行；另加一个按设备业务 ID 查名称的自然语言问题。未验收全库、所有业务接口或所有工作流。
- 每次业务查询先检查执行计划，串行执行，3 秒查询上限。首次计划审阅发现一张约 1,606 行的小关联表扫描；只对固定四表场景开放已审阅的小范围例外，未改动索引。没有业务数据写入、在用数据源绑定变更或远程数据库访问。
- 验收代理每次启动最多 40 个模型请求、480 秒总预算、90 秒单请求绝对期限；这些是测试限制，不是产品默认 SLA。

## 首次真实测试结果

| 场景 | 时间 | 结果与解释 |
| --- | ---: | --- |
| 四表独立 SQL 基准 | 16 ms | 返回 10 行；不包含服务身份检查、导入和连接初始化时间 |
| 当前 HTTP 分析查询接口 | 250 ms | 返回的 10 行 × 10 字段与独立基准一致，历史接口恢复后仍一致 |
| 四文件复杂交付 | 67.375 s | 首段文字 2.859 s；7 个真实模型请求累计 64.219 s，10 次工具启动事件。生成 JSON、Excel、Word、PPT，但 PPT 内容验收失败 |
| 同任务只修改 PPT | 14.094 s | 新 PPT 确实生成且保持任务标识，但改错物理页码，平台误报缺少其他三种文件 |
| 自然语言查单个设备名称 | 14.375 s | 首次工具活动 3.344 s，首段回答 12.734 s；4 个模型请求（含一次 SQL 生成）、一次实际业务 SELECT。名称正确，但删除条件扩大到 NULL，不符合既有严格零口径 |

这里的时间是单次观察值，不是平均值、P95 或性能承诺。SQL 时间和任务端到端时间不可混用。四文件任务的主要耗时在模型请求，而非本次查询的数据库执行。

首轮结构化保真检查：JSON 的 10 行原字段、值、类型和行序匹配；Excel 的 10 个表头及 100 个值匹配。此样本没有 NULL 或完全重复行，不能用它证明所有空值、重复行和大数据场景。Word 点位表完整，没有把计划要求写成实际已完成或逾期，但把未提供日期说成空值、把用量擅称单次用量，需要收紧口径。

PPT 的首次失败有三项独立证据：实际五页是封面、概览与周期、保养要求、待确认与行动、结束页，不符合五个主题各一页；10 条明细只有 7 条留在页面，余 3 条宣称在备注中，但 OOXML 中没有备注部件；要求修改第 3 页，ZIP 差异却仅在 `ppt/slides/slide4.xml`。

首轮报告：`live2/result.json`；独立内容审计：`content-audit.json`；自然语言报告：`model-query/result.json`。首次临时 SQLite 种子缺少时间字段的测试脚本错误保留在 `live/result.json`，该次没有发出业务 SELECT 或模型请求。

## 功能修复与复测

本次按真实失败修复以下契约：

1. 已有任务续改时优先使用本轮交付要求；纯“继续”保留原要求。历史文件继续保留，要求新版文件时必须核验本轮新工件。
2. PPT 显式控制封面和结束页，五个已指定的内容页不再被默认封尾挤成三页；旧默认行为保持兼容。
3. 区分用户看到的物理页码和正文索引；续改按完整页码映射定位。
4. 表格溢出真实写入备注，返回可见行与备注行信息；不再只留下指向不存在备注的说明。
5. 文件扩展名避免重复；文档技能区分未提供字段、数据库空值和未经证实的业务口径。
6. 对已知设备业务的“未删除”自然语言查询落实既有删除条件，防止 NULL 被模型擅自并入。
7. 辅助模型历史转换改用 DSH 原生消息构造器，补齐 assistant 的来源与消息 ID、tool 结果的调用关联 ID；修复携带 assistant 历史的第二次调用报 `replayState` 缺失。

| 修复后复测 | 时间 | 实际核验 |
| --- | ---: | --- |
| JSON + Excel + Word + 五页 PPT | **67.688 s** | 首段文字 2.922 s；8 个模型请求、10 次工具启动事件。JSON/Excel 各 100/100 原值及类型一致；Word 10 行×6个明细字段及4个共享字段正确；PPT按五个主题依次生成 |
| 同一任务只修改物理第 3 页标题 | **14.125 s** | 终态 completed；同一 task/draft；第 1、2、4、5 页 XML 逐字节不变，第 3 页仅标题改变；其余已交付文件保留 |
| 自然语言查询 + SQL 校验修正 | **16.656 s** | 名称符合独立基准；第一次不合口径的 SQL 在执行前被拒绝，第二次生成严格 `isDeleted = 0`；实际只执行一次 SELECT，未执行错误 SQL |

多文件复测没有重新查询 MySQL，复用已核验的附件快照。修复后的复杂任务模型请求累计 64.750 秒，包含网络、供应商等待与输出传输；不能将它等同于纯推理时间。上述两次复杂交付的时间接近，修复证明的是内容与续改契约改善，没有宣称性能提升。

表格完整性有明确显示范围：PPT 第 2 页仍只显示 7 条，另外 3 条现已真实写入关联的备注 XML，10 个点位全部保留；最终回答正确说明了这个范围。新旧 PPT 的内嵌图表 Excel 二进制变化只来自 `docProps/core.xml` 的 created/modified 时间，其他 9 个成员逐字节一致，图表单元格不变。原始验收误把这种时间变化计入内容变化；`artifact-revalidation.json` 保存二层 OOXML 复核，旧报告保留。

生成文字仍有两处轻微不一致：概览称周期为 30 天，待确认页又把单位是否为天列为未知；模型原备注首句仍称 10 行已列于页面，与实际 7 行可见不符，随后追加的备注及最终回答已正确说明 7+3。这些没有被隐藏或人工改稿后冒充模型结果。因此结论是本样本数值、结构和续改通过，不能声称整份生成文稿语义完全准确。

SQL 修复中间还实测到一次辅助模型适配失败：第一次生成后的纠错历史含 assistant 消息，原生接口因缺来源字段而失败。该失败样例耗时 33.032 秒、没有发出业务 SELECT；修复消息转换后，同一问题实测发生了一次成功纠错。离线同时覆盖 OpenAI 与 DeepSeek Messages 两种原生协议。

原始证据分别为 `delivery-fixed/result.json`、`delivery-fixed/artifact-revalidation.json`、`content-audit-fixed.json`、`model-query-fixed/result.json` 和 `model-query-final/result.json`。本轮总计 **39 次真实模型生成请求**，上游 HTTP/传输错误为 0；本机业务数据库 **6 次连接、5 次业务 SELECT、82 条已记录 SQL/控制命令**，包含首次小表冒烟、计划审阅、独立基准、接口查询与两次自然语言查询。没有数据库超时/断连停止事件。

## 长任务能力的实际边界

原生 DSH 已承担连续模型与工具调用、会话历史、队列、流式事件以及任务与草稿的续接。浏览器断开不等于取消；重启会恢复尚未执行的队列，并将已进入原生执行却没有终态的任务标记为中断，不承诺在任意工具内部无缝恢复。

当前尚无产品级整项任务总时限、总模型轮次或累计 token 上限。默认模型流空闲超时为 300 秒；有持续输出时不等同于整次响应 300 秒封顶。配置的最多两次重试按模型步骤计算，不是整个长任务总共两次。工具并发为 1、活动会话默认上限为 4，但队列长度和等待时间没有统一到期策略。

取消为协作式：Host 等待 Worker 和已启动工具响应，RPC 默认没有固定期限，不能保证任意挂起工具在固定秒数内停下。标准启动器关闭时有 15 秒外层进程树兜底，不能等同于每个聊天任务都具备同样的停止期限。网页检索、执行中 steer 和交互提问仍未接通。

因此，分钟级多步骤样例可以给出本次实测结论，数小时任务、百万行数据、并发压力、压缩后的长期记忆和所有复杂统计口径仍未验收。交付存在性校验也不等同于全面的数值、业务语义和版式校验。

## 复现入口

`tests/dsh/live_baseline.py` 生成独立本机只读基准，必须通过 `--device-id` 或 `LIVE_BASELINE_DEVICE_ID` 显式给出单个已审阅设备标识；代码不携带本次真实业务 ID。`tests/dsh/live_business_acceptance.py` 运行真实 DSH/Worker/模型验收。`--baseline` 复用同轮基准，`--skip-api` 在只复测交付时避免再次访问业务数据库，`--model-case query` 单独测试自然语言取数。业务数据库异常 STOP 存在时禁止启动后续测试。

原始基准不可盲目跨环境复用；应先重新核对本机服务归属和样本范围。真实测试会产生模型费用和临时平台记录。模型代理、查询预算与离线回归文件均在 `tests/dsh/`。
