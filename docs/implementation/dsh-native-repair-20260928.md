# DSH 原生接入修复验收

日期：2026-09-28。对应用户要求：完整使用 DSH 原生执行机制，解决复合任务需要拆句、查询口径错误、大屏不显示、任务堆积和运行中不能滚动。

## 已实施行为

- 宿主直接继承固定 DSH 0.1.7-alpha.2 的 base bundle 和 standard preset，不再手抄精简的工具组合。原生工具循环、todo、提问、压缩、文件、任务和子代理由上游实现；企业适配层负责身份、工具、持久事件和交付。
- DSH 查询工具提交明确 SQL，schema 提前返回可核对的原始时间/部门范围。SQL 不再被改回自然语言交给第二个模型。旧分析页面显式自然语言查询仍保留。字段、范围或业务语义不合格时返回结构化纠正信息，由当前 DSH Agent 修正。
- 财务验证依据授权元数据及 SQL AST 字段来源。应收/回款与应付/付款、合同额不能混用；改别名、CTE、UNION、CASE、COUNT 不能隐藏实际来源；关联必须有已确认关系。混合请求可按真实子任务分别取数，后续“改为应付”能更新原要求。
- 相对日期固定在服务器任务提交日期，支持年月、中文月份、完整日期区间、近 N 天及自然周/季度；同轮补充“改成七月”继承未改变的部门和指标。尚不能证明的复杂时间表达返回具体原因，不通过猜测跳过范围。
- 原生问题可在当前消息里回答，回答前不默认选项；todo 紧凑展示在当前消息。运行中补充通过 native steer 进入同一个运行，排队入口独立，历史保留各条用户消息。
- 原生子代理继承当前业务工具、技能、身份及模型预算；宿主等待后台子代理、所属 Jobs 和原生父代理的后续总结再结算。Jobs 采用纯观察，不消费输出、不抑制原生通知。停止/关闭同时取消所属子代理和 Jobs。崩溃时没有完整业务结算证据的后台委派/命令标记 interrupted，不借用较早的 completed，也不自动重放业务操作。
- 原生 write/present 可生成平台标准工件和下载卡片。同路径相同内容幂等，修改内容形成版本，旧版本不重复计入交付数量。
- 大屏交付必须有真实 Report、当前任务来源、成功业务查询、对应的原样数据快照及可见画布组件。仅有 profile 诊断、错误来源、被改写数值、画布外组件或旧大屏不能充作交付；缺失时业务状态 partial，与原生运行状态分别保存。真实空查询可以交付明确空状态。
- 保留原有界面样式；删除底部任务堆叠和资源发现卡片。流式渲染复用消息/iframe DOM，用户上滑后不强制拉底；填写追问时补偿上方正文增高，避免手机提交按钮漂移。静态资源版本更新为 `20260928-native-dsh-3`。

## 数据结论边界

本次没有修改业务数据、索引或工作流绑定，没有扩大此前对本机 szh_new 的查询预算。真实模型验证证明完整原生执行链能够在已知数据口径下完成单句复合任务，不能证明 szh_new 的真实应收表、附件或 API 已完成业务映射。此前发现的付款/合同数据不能被重新命名为应收；未确认来源时返回具体缺口。原计划中的 `resolve_business_metric` 等名称仅为后续专用适配建议，未假称已注册。
