## 环境与实际覆盖

- 本机 `127.0.0.1:3306/szh_new`，进程为 MySQL80 原生 `mysqld.exe`，已核对监听 PID、服务 PID 和程序路径。没有使用远程数据库。
- 当前数据库目录：437 张表、8448 个字段。当前选中数据源保存了 435 张表的元数据；旧对话中的 353 张不能作为现状。目录数量不同并不直接证明业务数据缺失。
- 业务读测涉及资金支付汇总、库存、备件、仓库；另复制仓位的授权元数据。真实模型仅能访问这五张表的现有授权元数据及已声明关系。没有声称逐表读取了全库437张表。
- 对实际查询先评估执行计划，串行执行，单条3秒；累计7个本机连接、101条记录的数据库命令，其中10条为业务SELECT，其余是会话设置、元数据、执行计划等。无业务数据、索引、全局参数或在用工作流绑定修改；本轮无数据库超时、断连或资源故障。
- 平台使用临时 SQLite，新启动最新 Node DSH＋Python Worker，不依赖常用8011服务的旧进程。
- 真实模型：OpenCode `deepseek-v4.1-flash`；本次测试档位显式设置32K上下文、4096输出、每轮240秒。结论对应这一受测配置，不等同于所有模型档位。
- 平台账户、模型、工具技能、会话、数据接入、分析、文件、文档、知识库图谱、报表、工作流、设备质检、运维、应用共14个注册域由隔离测试覆盖；真实业务数据测试集中在财务与库存。生产写操作、远程系统和全表压力测试不在已通过范围。

## 独立SQL基准与真实接口

独立基准包含全部未删除资金支付记录的数量及四类金额总计、按部门分组，以及库存关联物料和仓库的前10条。实际返回为1行总计、4行分组和4行库存；资金支付范围79条有效记录。

真实HTTP `/api/v1/analytics/query` 的资金汇总和库存关联均逐行逐字段等于独立基准。首轮接口端到端耗时分别187毫秒和110毫秒，不包括模型规划。修复后的AI实际执行3次业务查询，总计、部门分组、库存关联均与基准一致。Excel下载后读取单元格并按重复行、空值和十进制金额比对，三个文件通过；财务PPT中四项金额也通过。

PPT比较器曾把 `3685447.80` 与其标准化数值的尾零差异误报，已改为十进制数值比较并补测。原始 `result.json` 保留，离线重读已下载文件后的纠正记录为 `live-scope-fixed/reviewed-result.json`，没有为修正验收器再次查询业务库。

这里只能说明上述实际字段和返回范围准确，不能据此宣称全业务或所有AI回答“100%准确”。

## 真实复杂长任务

一次请求要求：资金总计及按部门汇总、库存关联查询、两份Excel、财务PPT、数字大屏、另一份5页ERP介绍PPT；成功后继续只改ERP第三页，其他页不变且不重新取数。

发现并修复的首要阻塞：`required_scope` 把“总计以及按部门汇总”当作具体部门限定，正确SQL在数据库执行前被拒绝8次。修复区分按部门/各部门等分组维度与设备部门等明确筛选，并将回归加入统一验收入口。

剩余长任务阻塞：32K档位中工具定义与上下文占用较大，首次模型输入已约24K token。修复后仍有6次无效压缩，其中2次摘要比待压缩内容更大，4次摘要达到输出上限；最终回答也以输出上限失败。根据代理请求时间与压缩事件对应，这6次请求累计94.39秒，占任务151.782秒的62.2%。这个问题不属于SQL性能；增加数据库接口并不能直接消除这些模型轮次。

另外，现有 `export_query_spreadsheet` 只接受单个query_id，模型把资金总计和部门分组分别导成两个文件，再加库存，共3份。需要让同源多查询以多工作表输出同一Excel，并让精确数量和内容完成条件参与验收，而不只检查“至少有若干附件”。新验收器已加入精确文件数量检查。

## 大屏与界面修复补充

实际生成的大屏为1920×720，原字号按宽高缩放比例的较小值计算，导致较宽的画布文字过小。已改为按聊天预览宽度确定基准字号，各组件仍按真实槽位高度适配；自动生成的来源说明也设置了缩放字号下限。真实快照在三种宽度均通过可见性、几何与表格核验。另将1920×720加入合成矩阵，防止只覆盖16:9模板。新增比例还暴露了短图表留白挤压绘图区的问题，已限制上下留白最多占组件高度55%；表格是否可同时容纳四行按缩放后的等效槽高判断，较矮槽位仍允许滚动并保留全部真实行。

实际截图仍显示英文SQL别名、以表格为主和长金额截断。这些问题没有因为字号测试通过而视为解决；还需要按已核实的字段语义提供中文标签、金额格式和指标/对比布局。`real-dashboard/saved-dashboard-1440.png` 保留了这一实际效果。移动端检查证明页面能显示和不横向溢出，并不意味着所有大屏文字在手机上都可直接阅读。

聊天外壳验收脚本修正了两项旧预期：原生SSE连接不能以networkidle0判断刷新结束；DSH任务归属会话，运行时允许切换到另一会话，不能继续使用旧循环的禁止切换断言。移动触摸验收改为先观察惯性滚动稳定，再检查持续流式输出是否强行改变用户位置，保留原有位置误差限制。实际模块切换、历史恢复、桌面滚轮和移动触摸回归已通过。
