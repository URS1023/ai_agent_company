# 内部业务接口与数据合同修复记录

本轮按实际源码核对 AI 工具、业务服务、普通页面接口和导出文件之间的数据合同。这里记录预警与目录部分；库存确定性查询、低代码字典同步、查询结果生成 PPT 由同轮其他实现覆盖。没有将静态注册完整或部分回归通过解释为所有业务功能均已实测。

## 已修复的具体问题

1. **预警报告和问题分页不能分别推进。** 旧接口只接受一个 `offset`，报告数量和问题数量不一致时，续读一类记录会同时推进另一类。增加 `reportsOffset`、`problemsOffset`（工具参数为 `reports_offset`、`problems_offset`），省略时仍兼容旧 `offset`。返回 `reportsPage` 和 `problemsPage`，分别提供真实返回数、下页起点和 `hasMore`。
2. **两页记录的关联不够明确。** 返回 `relationship`、`returnedProblemsInReportPage`、`returnedProblemsOutsideReportPage`。报告的问题总数与本问题页的条数不再只有相同的模糊“问题数”含义。严重性统计明确只针对已返回问题。首个完整授权页才给可知总数；起点超出记录范围时不会根据 `offset + count` 伪造总数。
3. **预警 Excel 的来源页无法复现分页。** 现在同时保存报告和问题的分页起点、下页位置以及关联数量；工件元数据保留同一范围说明。只导出已取得的结果，不额外请求设备或执行工作流。
4. **目录发现暗中变成数据同步。** 旧源首次读取目录时会构建语义索引，可能访问 MySQL 的低代码元数据表及调用向量模型。增加 `cached_only` 模式，目录发现只读平台中已经保存的元数据、外键、声明关系和向量，不访问业务数据库、HTTP 来源或模型。显式同步仍保留原来的完整行为；有效版本的既有关系和向量不会被目录读取清空。
5. **字段摘要丢失关联必需字段。** 旧摘要只输出表的前 20 个字段，且没有主键、关系和裁剪说明。现在优先保留主键、业务主键、名称字段、外键两端及声明关联字段，输出真实字段总数、返回数和裁剪标记。低代码枚举、字段类型、字典完整性和来源同步透传，长枚举明确标记裁剪。
6. **原生对话缺少旧预警事实保护。** DSH 的纯预警回答现在在结算时使用本轮成功工具回执生成简短摘要、重点问题和处置状态，报告完成不能写成人工已处理。失败的后续读取使先前范围不能冒充完整答复；追问没有本轮证据时也不能沿用旧答案。库存和文件制作等复合任务保留其完整正文。模型失败时保留已读事实，但技术终态仍为失败。该校验约束最终答复、历史和最终替换事件；不宣称逐个约束模型尚未结算的临时流式文字。
7. **冷目录覆盖已保存关系。** `query_business_data` 的 schema 模式也统一为纯缓存召回。即使尚无语义文档，也保留授权快照内已声明的关联及名称字段，并复核关联两端的字段可见范围，不能被空语义索引覆盖为无关系。

## 已执行的隔离验证

使用 `tests/run_isolated_backend.py`，平台为内存 SQLite；业务查询为临时本地 SQLite；HTTP 为本机临时桩服务。没有连接真实业务库、模型或当前运行中的 8011/8012 服务。

最终组合命令：

```powershell
.\.venv_py312\Scripts\python.exe tests/run_isolated_backend.py tests/backend/test_business_data_contracts.py tests/backend/test_alert_spreadsheet.py tests/backend/test_alert_problem_paging.py tests/backend/test_business_ai.py tests/backend/test_analytics.py tests/backend/test_alert_chat_evidence.py tests/backend/test_alert_history_grounding.py tests/backend/test_alert_receipt_scope.py tests/backend/test_business_worker.py --disable-warnings --show-capture=no --junitxml=.implementation/internal-api-data-contract-tests.xml
```

最终结果：**132 passed，0 failed，0 skipped，146.58 秒**，记录于 `.implementation/internal-api-data-contract-tests.xml`。包含新增数据合同回归，以及预警分页、导出、业务动作、分析查询和原生 DSH Worker 回归。新增 HTTP 合同验证了：目录发现零请求；固定 HTTP 源拒绝 SQL；AI 工具只发送一次已保存请求；十进制 `123.450`、布尔 `false` 与行来源保持原值；查询历史保留真实 `queryId`；整个固定接口查询不需要 SQL 生成模型。

初次扩大回归发现若干旧聊天测试仍替换 `runtime.agent._llm_stream`，与当前执行链不匹配，导致旧 OpenWebUI 客户端读取已移除配置文件。已将受影响的业务动作、预警证据、跨轮事实与失败范围测试改为原生 Worker 的 `prepare / tools.execute / settle` 协议；只有模型配置使用本地桩，业务工具、查询、事件和持久化仍使用正式实现。迁移同时发现并修复了上述原生预警事实保护缺口。最终组合不排除这些测试，也不恢复旧生产引擎。
