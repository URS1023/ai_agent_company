# 业务数据分析与核验

先明确来源、时间范围、维度、指标、空值与去重规则；信息足够时直接执行，不能反复询问已明确条件。

元数据关键词检索返回的是候选表，不能仅凭几次候选搜索就声称已逐一核查全部表或全库不存在某项业务。缺少应收台账的确认口径时，应说“本次检索尚未确认应收来源”，保留已确认的应付任务并按用户选择继续；合同剩余金额不能仅因名称相似改称会计应收。过程说明与最终答复跟随用户语言，中文任务使用中文，避免把英文推理过程逐条展示。

候选覆盖不足时先扩大一次检索，再批量核对关键表字段；若下一次仍返回相同候选，不继续轮换同义词。已有表结构不能支持目标口径时，说明具体已检索范围及缺口，继续可独立完成的交付。复杂联表需要的新关系和不同业务领域仍可继续查证。多交付任务只询问会改变数据真实性或用户目标的必填项；汇报型 PPT、未指定时间时的本次已有范围、通用 ERP 介绍等可按明确说明的合理默认继续，不把样式与可推断用途打包成多个必答问题。

大结果的相关表字段用 `read_tool_result(json_pointers=["/data/tables/0/columns", "/data/tables/1/columns"], fields=["columnName", "dataType", "comment"])` 一次批量读取；字段说明实际键通常为 `comment`。只读取本步相关表，不把所有候选表逐一拆成独立模型轮次。部门、客户等编码优先根据已确认关系或枚举解析名称；未解析时保留真实编码与空值，不能把不同查询里排序后的第一行都叫“部门1”而暗示同一实体。需要核对分组与总计时先对原始快照精确计算；未经计算不能写“不一致”或归因为数据库原始错误。

DSH 对话由当前 Agent 负责规划、选表、生成和修正 SQL。一般取数先 `query_business_data(mode="schema", query="当前取数问题")` 读取真实授权表字段，再 `mode="sql"` 提交明确 SQL，并提供 `task="当前取数子任务"`。完整原话、原始范围、已选来源和会话由服务端保留，不能用 task 改写它们；工具只做确定性校验和执行，不隐式调用另一个模型重写 SQL。`natural_language` 在 DSH 中会返回需要修正的模式错误，不应反复调用；独立分析页面的自然语言功能不受此约束。

日期依据任务提交时的服务端日期解释，月度 SQL 使用同一真实日期列的 `>= 月初 AND < 下月初`，不依赖数据库 `CURRENT_DATE`。原话明确部门时保留名称等值条件，不猜部门 ID。多个月份或部门的复合任务，可用 `scope.request_quote` 逐字引用当前步骤包含完整限定的原始子句，用 `scope.time` / `scope.department` 的 `table`、`column` 绑定真实字段；单一原始范围不能靠缩短引用删除。收到 `expected_scope`、`expected_conditions` 或 `semanticValidation` 时，依据真实 schema 修正当前 SQL 后继续，不重新调用隐藏规划器，不把可修正的字段/SQL问题直接推给用户。

“最近/过去 N 天”支持 1–366 个自然日，含提交任务当天，结束边界为次日零点；本周/上周按周一至下周一，季度按自然季度。回执给出实际起止日期；跨年月份和上一季度由服务端日期确定。同比、环比、开放日期边界等需要明确各比较范围与业务日期列，不能为了通过校验删除原话里的比较或截至条件。同轮用户补充“改成七月”时沿用未修改的部门和指标，仅按最新补充更新月份。

当前备品备件库存、仓库目录、物料目录优先使用确定性接口 `query_inventory_data`，分别传 `kind="inventory"`、`kind="warehouses"`、`kind="materials"`。传入本次已选择或唯一确认的 `datasource_id`；需要筛选时使用真实 `warehouse_id`、`material_id`、`name`、`batch_number` 和分页参数，不让模型重新生成这些标准查询的 SQL。库存结果已返回的仓库/物料名称直接使用，不为了补名称反复查询同一库存。

仅查看库存、单位及库存预警时，调用一次 `kind="inventory"` 即可，回执已包含所需名称、单位、阈值和范围。用户没有另行要求仓库或物料目录、当前字段也不缺时，不附带查询 `warehouses`、`materials`；物料主数据页不能解释为“这些物料没有库存”，没有出现在本页的实体也不能推断为零。

用户指定的部门、历史时间区间、趋势或特殊汇总等不在该接口筛选范围时，使用 `query_business_data` 的 schema 与 sql 模式保留完整条件，不把当前库存快照冒充历史区间；不得把库存查询参数用于仓库/物料目录后忽略不支持的条件。明细、汇总等不同取数步骤各自使用明确 SQL 和 task，同一成功结果直接复用，不为每种交付格式重查。

从有限范围开始，没有匹配记录就说明“本次范围未查到记录”，不编造样本。零行、`COUNT=0`、金额字段为空，均不能直接解释为营收或应收为 0；只有业务口径已确认且实际金额聚合返回数值 0 时才可报告金额为 0。上述两种业务查询成功回执中的 `queryId` 就是后续工具需要的 `query_id`。后续分析、图表和导出复用这个标识；大结果仅引用摘要和产物，不重复塞入全文。`totalCount` 是本次返回行数；`truncated=true` 时仍有未返回记录，不能宣称全库总数或查询全量。

零行且需判断该表是否覆盖所需月份时，先依据 `schema` 回执选取明确的表名与真实日期字段，调用一次 `query_business_data(mode="profile", table_name="实际表名", date_column="实际日期列", query="核对日期覆盖")`。该模式只查询单表未删除记录的记录数、空日期数、最早和最晚日期，固定返回一行，不调用模型、不自动同步元数据。`evidenceKind="coverage_only"` 和 `profileQueryId` 标识覆盖诊断，不能作为财务金额统计或大屏业务查询标识；同一轮相同参数成功回执直接复用。最早/最晚日期只表示边界，不能证明期间每个月都有记录；单表诊断不能证明整个数据源不存在相关业务。

正式业务查询始终保留用户原始月份、部门、客户等范围。DSH 路径不会重定向规划 SQL；回执 `generatedSql` 是经过权限、字段与行数校验后实际执行的 SQL。诊断结果不授权扩大业务范围；不得为了查出数据而反复换 SQL、改月份或换成不同业务指标。合同额、订单额、回款和应收余额的口径不能互相替代。

查询 Excel 用 `export_query_spreadsheet(query_id, name)`；数据 PPT 交给文档交付插件的 `export_query_presentation(query_ids=[...], title, name)`。同一数据任务的 Excel、PPT、图表复用同一批成功查询标识，不为每种附件重查，不向生成工具重新抄入数值。只使用本轮可调用的工具，选择了单一技能且缺少文件制作能力时说明缺失能力，不虚构交付。

查询结果导出时使用 `export_query_spreadsheet(query_id, name="业务名称.xlsx")` 一次确定文件名，不先生成默认名称再改名。该工具返回的是 `artifact_id`，不能把它传给只接受工作区 `file_id` 的 `rename_file`。

库存数量必须保留物料和计量单位口径；不同物料、不同计量单位不能直接相加，例如不能把油品与圆钢的 2、120、90、4 合称“库存总量 216”。单位缺失时保留原始明细或按物料分别统计，明确单位待补充，不自行换算或汇总为一个总量。

`unitConsistency` 对照每条库存与其关联物料的单位，逐条匹配不表示不同库存记录都使用相同单位。根据 `unitCounts` 与原始单位字段说明实际单位分布；面向用户只说业务事实，不照抄适配器名、`truncated=false`、查询参数或内部标识。

安全库存、预警阈值或实测库存为空时，预警状态必须为“未知／待补充”，不能将空值当作 0，也不能让 `CASE ... ELSE '正常'` 把缺失阈值判为正常。已有回执显示的“正常”若来自这种空值比较，应明确其不可作为正常或补货依据；按现有查询回执核对后生成新的交付，不覆盖历史文件。

数据库超时、断连、资源异常时停止相关访问，不重试、不扩大超时、不换源。一般参数或模板错误可以修正后继续，不能将历史无关工具失败解释为整个对话永久不可用。

## 工具与执行边界

工具：`query_inventory_data`、`query_business_data`、`export_query_spreadsheet`、`list_business_data_sources`。

本 Skill 提供业务方法；工具参数校验、身份、任务草稿、交付记录由插件代码负责。只使用本轮实际提供的工具，未注册工具不能假装已经调用。任务结束时按真实工具与交付记录说明完成、部分完成或失败。
