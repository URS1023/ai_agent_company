# 工作流测试数据生成器

双击项目根目录的 `start_workflow_data_gui.cmd` 启动独立 Windows 桌面界面。使用项目已有 Python，无需安装额外桌面框架。

1. 左侧选择工作流，可按产品质检、设备巡检、保养、维修筛选，也可 Ctrl / Shift 多选。
2. 设置每条工作流的数据数量，选择全部合格、全部不合格或随机混合；混合模式可设置不合格比例，按每条工作流的数量四舍五入。
3. 点击“生成预览”，查看每条记录的预期结果和实际标准；这一步不会写入数据库。
4. 点击“写入本地数据库”，整批新增业务源记录。时间以写入为准，后续定时工作流按运行时间窗口采集，不会自动重跑工作流或调用模型。
5. “历史批次 / 撤销”可删除本工具该批次新增的记录。已生成的工作流报告不会随源记录删除。

支持当前已发布的 18 条设备工作流和 9 条质检工作流。每条 1–20 份，每批合计最多 50 份单据/任务，包含关联明细后不超过 550 行。设备样本在所选工作流的设备范围内随机分配。预期合格/不合格针对本批新增记录；工作流可能同时检查原有计划及其他记录，因此整份报告不保证全部正常。

## 缺少标准时的处理

界面提供“补充测试标准/独立测试计划”选项。原有标准完整时，按数据库实际阈值生成检测数值；不合格质检单至少包含一项不满足标准的实测数据。

- 电石气体项目原配置缺少阈值时，使用“测试参数”中的明确测试值，只写入新建单据明细，不能视为生产标准。
- 原产品未关联对应模板时，复制现有“筛分楼石灰模板”或“筛分楼焦炭”的标准，新增带批次标记的测试模板并关联工作流对应产品。
- 设备缺少完整巡检/保养计划时，新增独立测试计划及关联记录；测试保养计划总周期为每周，润滑点周期可设置。
- 以上补充内容会出现在预览中，跟随批次一起撤销；原模板、原计划和工作流配置不被修改。关闭补充选项后，缺少依据的场景会明确停止预览。

## 本地边界与数据记录

只允许本机 MySQL 3306 的 `szh_new`。启动时核对监听进程、数据库主机和本机数据目录；不支持局域网、远程库或转发连接。数据库凭据读取项目配置，不写入批次文件。

记录 ID 使用独立 `GUISIM1-` 前缀；单据、计划标注 GUI 测试及批次号。批次记录位于 `storage/workflow-test-data/`，写入前保存操作记录，全部 SQL 使用参数绑定及事务。不要手工修改批次文件；撤销按其中的新增记录 ID 精确执行。

数据库异常时停止操作，不自动重试。写入结果未确认的批次保留为“需核对写入状态”，避免重复生成。为避免预览耗时和秒级时间边界影响增量采集，创建/更新时间在提交前统一设置到当前时间约 2 秒后。

验收记录：`.implementation/workflow_data_gui/`。验收采用事务回滚，没有永久添加验收数据。
