# 节能分析

面向维护本模块的开发、测试人员。`router.py`负责权限和DTO，`service.py`负责取数、事务与来源，`analysis.py`为可独立复算的纯函数。页面入口在预测性维护内的“节能分析”。

## 数据与计算

- 必须选择平台已授权查询，服务端重跑一次并拒绝截断结果。输入映射包含时间、两期标记、电量、同期产量、负载，配方/阶段等工况字段按实际选择。可通过源设备字段及编号限定设备；未配置时由所选查询限定范围，来源中明确保留这一选择。
- `interval`表示每条生产记录期间电量；`power`表示对应记录的平均功率，乘实际运行时长，不能将瞬时功率直接累加；`cumulative`对两期分别排序差分。累计表起始读数不算消耗，负跳变和跨工况区间舍弃并计数，不补算重置前电量。产量字段始终是对应区间产量，不是累计产量表。
- 电量统一换算kWh，产量保留明确单位。同一设备同一时刻的完全相同记录去重；内容冲突全部排除。缺产量、无效单位、工况缺失等计入数据问题，不能当成零。
- 两期须按时间先后且不重叠。时间保留原始字符串及UTC，按Asia/Shanghai提供观测范围和所在自然日的00:00起点、次日00:00不含终点；自然日边界只用于追溯，不把跨日区间或缺测补成整日耗能。

对配方/阶段相同、处于同一负载箱且两期样本足够的分组计算：

```text
基准单位能耗 = 分组基准电量合计 / 分组基准产量合计
按近期产量的基准电量 = 基准单位能耗 × 分组近期产量合计
分组电量差额 = 分组近期电量合计 − 按近期产量的基准电量
电量空间 = 各可比较分组正差额之和
```

整体单位能耗按近期各组实际产量加权，不对逐行比值取算术平均。零基准电量不作为可达到的节能基准。覆盖率取有效区间、近期匹配样本、近期匹配产量、可选时间连续性及两期顺序的最低值；低于指定门槛时，节能比例、空间、金额和情景收益均为null。

电量空间仅表示“历史基准可在近期同工况再次达到”的差额，不是已实施节约或保证收益。零产出用电单列为需要确认用途的证据，不将清洗/保温等直接认定为浪费。

## 金额与计划工时

仅全部匹配近期记录具有有效电价（元/kWh）时计算金额。按各原时段电价比较实际电量和反事实电量，不用部分平均电价补值；分组正电量差额的时段成本差额相加后以零为下限。金额最终按四舍五入保留两位，计算使用Decimal高精度上下文。

计划情景还必须显式提供计划小时，全部匹配记录有实际运行小时。按本次单位运行小时差额换算，并保留“未来工况组合、产量节拍、电价不变”的假设。缺运行小时不以日历跨度代替，缺价格不产生金额，不默认全年外推。

## 接口与生命周期

路径统一前缀`/api/v1`：

| 接口 | 作用 |
|---|---|
| `GET/POST /energy-analyses` | 列表或执行；执行需要m10.write及m06.read；返回201完整结果 |
| `GET /energy-analyses/{id}` | 结果、固定映射、来源、设备名与任务引用 |
| `PATCH /energy-analyses/{id}` | 仅revision/name；重新分析创建新记录，不覆盖结果 |
| `DELETE /energy-analyses/{id}?revision=...` | m10.delete软删除，保留运行事实 |
| `POST /energy-analyses/{id}/exports` | 实际分组CSV，包含单位、覆盖率和来源引用 |

所有历史查看、改名、删除和导出均重新授权实际运行query，并核对固定行摘要；撤权记录从列表及可见total排除，损坏证据不静默隐藏。统一Task保存执行状态，输出只含结果引用和业务状态。请求事务失败整体回滚，既有制造补偿机制仅另外记录失败Task或数据源阻断，不重试查询。

## 复用与验证

复用平台`maintenance.py`的同工况分箱、去重/冲突和覆盖思路，调整为按产量加权的精确能耗口径；复用DataService授权查询、字段AST安全层、TaskService、制造事务与CSV导出。Test5 `equipment_simulation/service.py:propose_energy`依赖模拟泵参数，未作为实数据算法复制。

`tests/test_manufacturing_energy.py`覆盖两期加权、价格不完整、运行小时、功率单位换算、累计表重置、数据冲突、缺产量、时区边界、时间重叠及来源撤权。数据库测试仅使用新建临时SQLite与4行新CSV，不连接旧库、外源、模型或设备控制接口。
