# Workbench

Enterprise conversation controls, application configuration loading and session transport orchestration.

## Internal Modules

- `documents.tsx`: generated-contract Office directory with bounded continuation validation, actor/workspace-scoped cache and exact-revision Word downloads using the native binary transport. Identity changes abort pending downloads and remount pagination; failures never fabricate files. The landing mounts this beside native applications only after its role gate. Creation, content editing, PPT rendering and production Office service wiring remain separate outstanding work.

- `launcher.tsx` and `session.tsx` generate branch/client-message UUIDs with the existing `uuid` package, not secure-context-only `crypto.randomUUID`. This retains random UUIDs on LAN HTTP browsers exposing `getRandomValues`. Real Chromium verified the installed UUID browser implementation on an insecure fixture origin; whole live LAN UI acceptance remains separate.
- `draft-state.ts`: feature-owned ephemeral Jotai draft map, keyed by workspace/account/app/branch. Restores text after same-session route remounts and resolves acknowledgement clearing against the latest value. Empty entries are deleted; nothing is written to local/session storage or the server. Active nonempty composers register a beforeunload warning and remove it on clear/unmount. This is not persistence across refresh, a global warning while other pages are active, or crash recovery; browser dialog behavior still needs live acceptance. Root app Jotai provider owns the memory lifetime.
- `resume.ts` / `history-page.tsx`: `/enterprise/workbench/[installedAppId]/history` lists account-scoped branches, reauthorizes the selected identity through the generated branch GET, loads native history, then rechecks the branch before adopting a snapshot. Uses saved head inputs, never current defaults. Selection retry is explicit, cached snapshots do not silently restore stale branches on reselection, and scope changes remount. Ready/archived branches with saved heads are supported; preparing/unused roots and first-send-without-head need a separate recovery/input flow. Selection uses the branch URL query parameter through nuqs with generated ID validation and push history, preserving unrelated parameters. Direct/external URL selection still reauthorizes; invalid branch query values show the directory without a resume read. Discard-draft confirmation and native conversation names/recency remain pending.
- `history.ts` / `history-loader.ts`: generated native message-page decoding and read-only snapshot loading after branch authorization. Uses `first_id` for older pages, validates conversation/message identities and follows parent links from the confirmed head, excluding sibling answers. Missing ancestors require more pages or fail explicitly; cycles, duplicate records, cancellation and the 100-page budget do not yield a partial success. Keeps native records separate from workbench send-ledger observations. Native nil parent denotes a root. The history route uses the resume owner to authorize and load these records before session mounting.
- `branch-directory.tsx`: generated-client branch listing with scope-keyed cache and cursor navigation, scoped loading/empty/error states and explicit retry. Validates generated response shape, actor/workspace/app identity, page bounds, duplicate IDs and continuation before showing entries. Emits selected branch context only; it neither resumes a transcript nor starts generation. IDs are shown without invented titles or recency. Mounted by the history route; selection passes through the resume owner.
- `composer.tsx`: text editing, IME-aware send intent and submission availability. The owner supplies localized labels, retains the draft and owns send acknowledgement, errors, idempotency and busy state. This component never clears a draft or sends a network request.
- `input-schema.ts`: adapts native wrapped application parameters, retains constraints and detached defaults, rejects unknown editable fields and skips server-owned external tools. Generated JSON schemas are permissive; native input and attachment validation remains authoritative.
- `scalar-input.tsx`: controlled native text, paragraph, number, checkbox and select fields. Preserves string edits and boolean values, links labels and respects disabled/hidden state. The enclosing form must initialize defaults, validate and submit; file and JSON fields require their separate controls and are not silently rendered as text.
- `json-input.tsx` / `input-json.ts`: controlled JSON-object text editing and parsing. Invalid drafts remain editable; omitted input is distinct from an empty object. Inline errors use existing workflow translations. The form owner must gate submission using the parser; this does not implement JSON Schema validation or replace native preflight. Non-finite numbers and unsafe integers are rejected rather than silently submitted as rounded values.
- `input-files.ts`: converts completed native uploader selections to existing native file references. Pending/failed selections block conversion rather than being filtered out; browser File, preview data and UI IDs are excluded. The enclosing form still owns cardinality, required fields, upload configuration and submission gating; native ownership/constraint validation remains mandatory.
- `input-file-defaults.ts`: restores configured native local/remote file metadata into initial uploader selections, retaining filename, size, MIME type and persisted references. No upload/metadata I/O or current-access assertion occurs. Incomplete metadata and unsupported reference kinds fail configuration loading; they are not filled with invented values. The application passes restored selections through launcher/form to normal submission validation.
- `file-input.tsx`: native attachment uploader integration using generated `UploadConfig`, preserving file type/extension/method restrictions and field cardinality. Native uploader owns its initial selection; scope/reset changes must remount the form. A stable callback forwards to the latest owner callback. The owner still collects progress state and uses `input-files.ts` to gate submission.
- `input-submit.ts`: aggregates client-side field errors and shapes a detached submission only when all configured fields pass the UI gate. Preserves hidden defaults supplied by the owner, ignores unrelated state keys, parses JSON drafts and blocks pending/failed or excess file selections. Existing file defaults must first be resolved into uploader selections, not silently omitted. This is not a substitute for native preflight.
- `input-form.tsx`: assembles scalar/JSON/file controls with owned drafts, selections and submit-attempt errors. Accepts caller-localized labels, optional real upload configuration and pre-resolved initial files. Scope key changes reset all field state; the route owner must include account/app/config identity. Busy launch disables edits/submission. Missing visible-file configuration blocks launch. Successful submission forwards the validated detached inputs, not a network request.
- `launcher.tsx` / `launch.ts`: explicit parameter submission creates an actor-scoped root through the generated business client, then mounts `WorkbenchSession`. Stable root ID survives explicit retries, automatic mutation retries are disabled, and synchronous reservation blocks duplicate clicks. Generated response validation checks all scope fields and requires a ready unused root. History resumption is separate. The application route loads configuration and mounts this launcher.
- `application.tsx`: adopts one successfully loaded configuration as the current editing snapshot and stops automatic configuration queries while it is in use. Later cache updates do not reset drafts or tear down a launched session. Account/workspace/app changes still remount, role restrictions still apply, and server-side authorization and input validation are not cached or bypassed.

## External Modules

- `app/components/workflow/types`: native input-kind vocabulary.
- `service/enterprise-business/workbench-send`: scoped one-POST streaming transport used by the session.
- `app/components/base/file-uploader`: native picker, upload lifecycle and selected-file UI.
- `app/components/base/markdown`: native sanitized Markdown, code/table rendering and stream presentation.

History, branches, attachments, resource selection, streaming/stop, business confirmation and artifact panels remain required. A passing composer test is not acceptance of those capabilities or of the final visual design.

## Turn state

- Native `message_file` events now populate immutable per-turn attachment metadata after full conversation/message/task identity validation. Repeated file IDs update signed URLs without duplicate cards; type/ownership conflicts are rejected. Live cards use the real file ID when native events omit filename/size/MIME, not a guessed extension or zero size. Files do not imply durable success. The same attachment view handles historical and streamed records. Terminal `message_end.files` has distinct easy-UI versus advanced-chat reference semantics and is not blindly treated as historical MessageFile IDs. After a durable terminal receipt and transport closure, `completed-files.ts` reauthorizes the branch, loads/revalidates its native lineage and selects the exact completed message. Session-owned Query observers replace provisional files with persisted metadata, retain provisional links on read failure, and offer read-only retry. No automatic retries, model replay or input/draft resets. Full-lineage reads remain bounded but need performance validation on long conversations.

- `turn.ts`: Pure immutable presentation transitions for a single client message. Uses the generated `WorkbenchSendState` schema for both SSE and scoped GET observations, while keeping transient native identity and text separate from persisted acknowledgement. Validates expected conversation and stable message/task identity; ignores older revisions and rejects conflicting/evolving terminal records. `message_end`, errors and transport closure never manufacture completion. A route owner must scope reads, retain client IDs, and connect these transitions to the composer and stream transport.

## Conversation view

- `history-media.tsx`: media-only content mounted inside an explicitly opened preview dialog. Uses the persisted MIME type rather than hardcoded MP3/MP4 assumptions. Closing removes the player; re-opening clears prior load errors. Error messages are localized and the surrounding original-file link remains available. No caption/transcript metadata is fabricated; actual browser codec playback and complete accessibility/visual acceptance remain required.

- `history-files.tsx`: native persisted attachment metadata rendered as keyboard-accessible file links within the recorded user/assistant message. Unknown ownership remains outside either speaker region. Opens valid HTTP(S) or root-relative URLs unchanged, including signatures; missing/unsafe URLs retain metadata without navigation. No invented upload IDs, sizes or download query parameters. Uses the native file icon and size formatter. Matching image/audio/video metadata opens an on-demand Dify UI dialog with native browser media controls and original MIME information; nothing autoplays. Invalid URLs or inconsistent type/MIME metadata remain non-previewable. PDF/document inline preview, extra contents and browser playback/visual acceptance remain pending.

- `conversation.tsx`: Controlled scrollable transcript and bottom composer, rendering validated turn snapshots and forwarding send/state-check intents. Unresolved or open turns keep new sends disabled; closed unresolved turns offer only a status-read action. The route owner still supplies draft state, generation transport, scoped state reads and history. Assistant answers now use native Markdown/Streamdown rendering with streaming state; user text remains literal. Generated form/button/input elements do not execute business actions. Artifact integration and full visual acceptance remain pending.

## Session orchestration

- `session.tsx`: Connects the controlled view to `sendWorkbenchMessage`, immutable turn updates and the generated scoped message-state query. TanStack mutation/query owns asynchronous status; an AbortController guards same-tick duplicate sends and cleanup. Account/workspace/app/branch changes remount the session. A scoped snapshot validates the supplied native history against the confirmed head and adopts detached inputs once; same-scope parent refreshes do not reset drafts or replace input values. A used branch with missing/foreign history shows an error rather than an empty writable conversation. Native history is rendered separately without invented durable outcomes; only a known in-flight ID is restored as a pending observation. The history route authorizes/loads the branch, history and saved head inputs before mounting. Historical attachments/extra contents and full visual acceptance remain required.

## Entry route

- `/enterprise/workbench` mounts `landing.tsx` behind the existing enterprise feature flag. The portal AI card links here. The landing preserves native installed-app links and adds workbench links for chat modes. `/enterprise/workbench/[installedAppId]` validates IDs, retains the rollout/role restrictions, loads account/workspace-scoped installed metadata and native parameters, then conditionally loads full upload configuration through generated queries. It mounts the launcher only when configuration is ready. Missing/unsupported apps and malformed/failed configuration do not launch. Existing `/installed/{id}` links are unchanged. File default hydration and real end-to-end acceptance remain pending.
