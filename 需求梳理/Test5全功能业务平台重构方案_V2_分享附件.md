# Test5 全功能业务平台重构方案 V2

日期：2026-08-31  
状态：持续实施中；已完成部分基础与分析能力，尚未完成全平台集成验收，详见实施记录。  
目标：业务后端统一 Python，在当前工作区实现完整企业业务平台。最新界面要求以 Qknow 的排布与布局为主框架，Test5 作为独立 AI 工作台模块，不作为产品首页或全站外壳；完整覆盖 Qknow 业务功能与 Lynx AI 数据分析、报表和大屏能力。

最新交互约定：正常业务界面是主体，参考 Qknow 的顶部一级业务导航、按域切换的紧凑二级菜单与页面标签栏。禁止把全部功能堆在左侧；Test5 收入 AI 工作台。用户不进入对话页面，也可以使用各业务模块；模型生成类功能可在所属模块内提供生成按钮，不要求用户先进入聊天。

## 2. 本轮重新核对的事实与限制

本节记录方案编制阶段的静态代码、路由、接口定义、菜单 SQL 和组件目录核对；当时未进行线上验收或数据库写入。后续已开展隔离测试库的实现与浏览器验证，最新进度以 `test5/docs/implementation/PROGRESS.md` 为准。

1. Qknow 顶层实际包含 11 个业务模块：`ai`、`app`、`dm`、`ext`、`kb`、`kg`、`kmc`、`system`、`alert`、`qc`、`report`，另有 framework 和 server。
2. 前端还按 `kac`、`kd` 等目录组织应用中心、解决方案和运营页面；只看 Maven 模块列表会遗漏这些业务。
3. 已核对 Qknow 中的物联网测点、告警配置、专家经验、知识资产看板、Bot 运营看板、应用运营看板、应用与解决方案入口。
4. 知识资产、Bot 运营、应用运营页面当前存在明确的“接口预留中”逻辑，真实模式返回空看板结构；不能视为已完成业务。
5. `/dm/point`、`/dm/config`、`/dm/advice`、部分 `/kac/*` 等前端接口，在本轮搜索到的当前 Java Controller 中未找到对应完整实现，应纳入补齐核对。此结论不等于已验证线上 404。
6. Lynx 的大屏定义文件包含 20 套模板。组件目录元数据登记 135 种组件类型、133 个主目录叶项和 8 组工具栏；这是目录基线，不代表每种组件已经验证完整渲染。
7. Lynx 已有独立的提示词分类/模板接口与 `ReportPromptLibraryPanel`，迁移不能遗漏它们。
8. Test5 已有 ToolSpec/ToolResult、工具网关、消息分块、Run/RunStep/ToolCall 和工件机制；新增能力应接入同一执行体系。
9. 源码中存在旧引擎地址、演示配置和开发期固定参数。新系统不能直接继承旧 token、演示凭据、固定页面 ID 或不明授权二进制。

## 3. 产品形态：正常业务系统与独立 AI 对话模块

### 3.1 常规业务界面是主体

- 登录后进入首页概览，显示当前用户有权限的业务摘要、待办、常用模块和最近资源。
- 点击数据分析，进入查询、数据集、结果、历史等分析页面；点击设备预警，进入规则、问题、报告等预警页面；点击用户管理，进入用户列表与管理表单。
- 数据源、模板、提示词、知识库、工作流、检测记录等都能通过所属模块直接创建、管理和查看，不必先开启对话或生成聊天结果。
- 模块页面可独立打开、刷新和收藏；正常加载不依赖一条聊天记录、AI 任务或临时对话上下文。
- AI 对话是独立模块。只有用户进入该模块时，才使用 Test5 的对话/任务布局；不在所有页面固定放聊天框，也不强制每个操作经过模型。
- AI 创建的资源进入对应业务模块的同一列表；手动创建的资源也能在授权范围内被 AI 引用。两种方式修改同一个有版本的资源。

### 3.2 AI 模块内的用户示例：财务与设备数字大屏

用户进入 AI 对话模块后说：“我想看财务和设备的数字大屏。”

系统应在已授权、已接入数据可用时完成：

1. 识别目标为生成综合大屏，而不是普通知识问答或页面导航。
2. 检索当前工作区可访问的数据目录，定位财务、设备、告警与可用指标。
3. 获取表和字段说明、业务口径、数据新鲜度、时间范围与允许的关联关系。
4. 选择所需能力和提示词，形成可执行的分析/生成计划。
5. 执行受控只读查询，校验统计结果与数据绑定。
6. 动态匹配合适模板或生成兼容布局，创建大屏草稿。
7. 在 AI 模块的结果区域直接展示真实可交互的大屏，支持钻取、筛选、刷新、全屏和继续修改；同一资源也可从报表大屏模块打开完整页面。
8. 显示数据来源、口径、时间范围和运行记录，允许继续说“换近三个月”“加设备异常排行”“用明亮模板”“保存这个做法”。

如果财务和设备没有可验证的关联键，可以在同一大屏分区展示两类数据；不得仅因字段名称相似就联表并得出关联结论。

“看大屏”默认生成个人预览或草稿。公开发布、定时运行、生产表写回、权限调整等行为需要相应权限和明确授权。

### 3.3 AI 模块的自动化与补充信息边界

- 已配置且在权限内的数据、模型、模板和工具自动发现，用户不必知道其路径或 ID。
- 存在工作区已确认的时间、单位和组织口径时可以使用，并在结果中说明；不猜测业务口径。
- 多个数据源含义冲突、必要口径缺失时，在对话里问必要问题并保留上下文。
- 数据源尚未接入时，在对话中提供安全接入卡片或提示管理员授权；不能声称已经查到数据。
- 密钥通过安全表单输入并由后端保存，不要求用户把凭据写入聊天消息。
- 上传本机未授权文件必须由用户选择/上传，AI 不任意读取整台电脑。
- 模型、数据库或检测服务不可用时返回明确状态，不能把演示数据当作真实结果。

### 3.4 三种入口共用同一业务能力

正常业务页面、AI 对话模块、外部 API 使用同一套业务服务、权限与数据模型。

- 业务页面是完整独立的日常操作界面，既服务普通用户，也服务专业人员和管理员。
- AI 对话模块提供自然语言任务执行和跨模块协作，是用户可选择的一种操作方式。
- 外部 API 用于系统集成。

正常页面直接调用业务接口，不需要经过意图识别或任务规划。AI 模块调用经过注册和校验的同一业务能力，不依赖模拟鼠标点击；AI 结果可复用业务组件，也能打开独立模块页面。

## 4. 统一架构

```text
常规业务模块页面 ───────────────────┐
AI 对话模块 → 资源/能力发现 → 任务计划 ├→ 统一鉴权/参数校验 → Python 业务服务
外部系统 API ─────────────────────┘                         ↓
                                               数据 / 工作流 / 后台任务
                                                          ↓
                                       资源 / 版本 / 数据来源 / 结果与记录
                                                          ↓
                                      业务页面 / AI 模块结果区 / API 响应
```

### 4.1 核心公共模块

- **应用外壳与模块路由**：首页、分组菜单、身份/工作区、面包屑、独立模块页面与路由权限；AI 对话布局只属于 AI 模块。
- **身份与授权中心**：用户、组织、角色、功能权限、资源/数据权限、会话和审计；所有入口和后台任务采用同一授权规则。
- **能力注册表**：业务能力名、说明、用户说法、输入输出、权限、副作用、版本、对应接口、执行状态和结果组件。
- **资源目录**：数据源、数据集、表字段、文件、知识库、图谱、设备、模板、提示词、已有报告和工作流。
- **业务语义层**：业务名称与真实字段映射，指标公式、单位、时间口径、粒度、维度、关联键、敏感级别与更新时间。
- **任务编排器**：基于目标和当前上下文选择能力，产生结构化步骤，处理必要追问、重试、取消和后续修改。
- **工具网关**：统一权限检查、参数校验、凭据注入、调用、限流、防重复、结果验证、审计。
- **运行与结果中心**：各入口触发的长任务共用 Run/RunStep/ToolCall，常规 CRUD 纳入统一操作审计；结果关联来源、模板/提示词/流程版本。
- **结果渲染协议**：以业务类型、资源 ID、版本和允许操作驱动前端组件，不让模型任意注入页面脚本。

### 4.2 关键约束

- 按业务域组织 Python 模块，采用模块化单体；队列 worker 单独运行，但不为每个功能建立微服务。
- 复用 Test5 的 auth/workspace/chat/files/knowledge/skill/plugin/connector/datasource/secret/artifact/presentation/runtime/capability/audit/model，按需扩展，避免重复实现。
- 新增 analytics、dashboard、prompt_library、workflow、bot、ontology、extraction、graph、alert、quality、applications、operations、asset_catalog、api_catalog 等领域模块。
- 模型负责解释、计划和生成候选结构；权限、SQL 安全、规则运算、金额与检测指标计算、保存和发布由确定性服务执行。
- 普通页面与非 AI 基础操作不依赖聊天服务可用性；依赖模型的生成/识别操作明确显示依赖状态，不能拖垮用户、数据源、规则和历史结果等常规管理页面。
- 能力搜索必须先做权限过滤，再向模型提供相关能力和参数；不把全系统所有接口及敏感资产一次性塞进提示词。
- 文档、数据值、接口说明和外部响应属于数据，不得覆盖系统授权策略。

## 8. 工作流、设备预警与质检的统一实现

### 8.1 工作流节点体系

通用节点包括：开始/结束、文件输入、HTTP、数据库查询、JSONPath、变量赋值、字段映射、算术、条件、分类、模板/文本处理、知识检索、LLM、Agent、工具/MCP、Python 代码、集合处理、迭代/有界循环、并行、聚合/合并、子流程、缓存、延迟、等待输入、通知/Webhook。

业务专用节点包括：设备数据采集、预警判定、外观缺陷识别、成分检测、质检判定、数据分析、看板生成、文档/PPT 导出、问题生成、目标表写入。

- 流程定义包含版本、输入输出 Schema、节点参数、连接边和执行策略。
- 工作流模块提供流程列表、完整画布、节点配置、调试、版本、发布、调度与运行详情页面；用户可完全通过正常界面构建和维护流程。
- 临时任务可以自动形成内部执行计划，用户不必先绘制流程。
- 用户要求复用或周期执行时，再保存为版本化工作流/Skill/Plugin；启用调度要明确授权。
- 自动生成的流程经过结构、参数、权限、节点可用性与循环上限校验。
- 业务节点调用同一业务服务，不再各自实现一套分析、检测或报表逻辑。
- 支持持久化状态、重试、超时、取消、暂停、必要的人工复核与安全恢复。
- Python 代码节点与普通运算分开；任意代码不能在 API 进程直接执行，隔离能力须专项测试。

### 8.2 设备预警

- 设备预警模块独立提供采集配置、规则编辑、测试预览、问题列表、处理详情和报告页面；同时保留 AI 模块中的“查看设备预警”场景入口。
- HTTP 与数据库数据源，单条/批量请求体配置、请求参数/头/鉴权、采集批次与单条失败定位。
- 字段发现与选择、JSONPath 样本提取、类型转换、空值与异常数据处理。
- 加减乘除、括号、AND/OR、交并差、等于/不等于、大于/大于等于、小于/小于等于、范围内/范围外。
- 明确集合匹配键、去重规则、范围端点、单位、精度与除零行为。
- 规则预览和正式执行区分；生成问题列表与报告，保存计算证据和规则版本。
- 创建/编辑页可手动选择来源字段、目标表和目标字段；AI 模块可从用户意图及授权资源目录解析同样配置，含糊时追问确认。
- 外部数据库写回使用独立写权限、允许的表字段、事务与幂等键；仅查询请求不能被解释为生产写入。
- 问题认领/处理/复核、处置说明、专家经验和关联报告保留。

### 8.3 质量检查

- 设备与检测服务能力、指标类型/单位/阈值、模板及指标绑定、模板版本。
- 外观：上传/采集图像、识别任务、缺陷类型、位置框、置信度、严重程度、建议和原图追溯。
- 成分：真实检测数据、单位与校验、范围判定、逐项与整体结论。
- 质检模块提供设备、指标、模板、检测任务、缺陷/成分明细、复核和报告页面；正常表单可创建模板、添加指标、提交检测、复核与导出，AI 模块可协同调用同样能力。
- 无服务或无真实测量数据时为待配置/未检测/需复核，不自动判定合格。
- AI 视觉识别能力与具体工业缺陷识别精度不是同一验收项，需设备/模型/样本专项验证。

## 9. 全接口注释与合集：一级交付物

### 9.1 同一契约，三类产物

1. 开发与集成：全量 OpenAPI 3.1 JSON/YAML、中文在线/离线文档、分模块接口合集。
2. 测试：Postman Collection、可供 Apifox 导入的规范文件、无真实凭据的环境模板、请求/响应样例与测试断言。
3. AI：从同一契约派生的能力目录、ToolSpec、业务别名、参数解析规则、依赖与结果渲染类型。

OpenAPI 的 operationId 用于唯一标识操作，本项目还将其关联权限、能力、审计和测试，不允许同一业务操作在几个系统里各自命名。字段、示例、响应与鉴权遵循 [OpenAPI 3.1 规范](https://spec.openapis.org/oas/v3.1.1.html)。Postman 支持从 OpenAPI 导入并生成请求合集，见 [官方导入说明](https://learning.postman.com/docs/design-apis/specifications/import-a-specification/)。

### 9.2 每个接口必须说明

- 中文名称、业务用途、适用/不适用场景、所属模块、版本与稳定 operationId。
- method/path、鉴权方式、资源/工作区/角色权限、请求头和内容类型。
- path/query/body 每个字段的说明、类型、必填/可空、枚举、单位、精度、范围、格式、关联资源和示例。
- 响应结构和字段、分页/排序、结果规模、工件/大屏/图谱等结果类型。
- 成功样例、参数错误、无权限、数据源故障、超时、部分失败及恢复方式。
- 副作用、事务边界、幂等、防重复、限流、超时、取消和异步运行状态。
- 前置依赖和后续相关接口，AI 参数解析与缺失信息的追问规则。
- 数据敏感性、脱敏、日志保留和审计要求。

Python 业务方法保留 docstring；Pydantic 字段配置 description/examples/约束；数据库表字段保留 comment 和业务语义。不能仅写“获取列表”“data 对象”就视为完整注释。

对于自由 JSON 字段，必须说明允许的结构并提供 Schema。工作流节点和大屏组件使用按类型区分的配置 Schema，不以任意对象替代业务校验。

`capability_id`、`operation_id`、中文业务描述、用户常见说法、输入输出 Schema、资源解析器、所需权限、读写类别、副作用、确认策略、幂等策略、执行依赖、版本、可用状态、结果组件、样例及测试编号。

例如 `dashboard.generate` 可组合元数据检索、查询、组件生成和保存；用户表达一个业务目标即可。低层接口仍完整文档化，但只在权限和执行计划需要时开放给 Agent。

新增/未实现/离线能力不得注册成“可执行”。API 文档全量不意味着普通用户拥有所有接口权限。

### 9.5 契约验收

- 新系统实际注册的业务接口全部进入文档和模块合集；内部/管理接口也登记并限制文档访问。
- 每个业务接口都能追踪至能力或明确的“仅系统内部/仅管理”标记。
- 缺少 operationId、权限声明、字段说明、响应或错误样例时，检查不通过。
- 文档 Schema、真实响应和前端类型由自动化合同测试核对。
- 合集导入和执行在本机实测，不能只生成一个无法调用的空壳文件。
- 发布时生成同版本文档、合集、能力目录和变更说明。

## 10. 正常模块界面、用户权限与 AI 模块的协同

### 10.1 整体布局：常规业务系统，不是全站聊天布局

- 登录后默认进入首页概览。参考 Qknow 的布局，顶部承载“工作台、数据分析、知识管理、业务应用、AI 工作台、系统管理”六个一级业务域；组织/工作区、搜索、通知和账号操作位于公共工具区。一级导航按权限显示，窄屏采用业务域选择器，不把全部业务域改堆到左侧。
- 左侧仅显示当前业务域的二级菜单，随顶部业务域切换；模块内部的详情、配置、历史等使用页内标签或独立详情路由，不继续扩大全站菜单。页面标签栏用于切换已打开的业务页面。
- 首页按权限展示业务摘要、待办、异常、最近使用和少量常用入口；无常驻侧栏，不默认渲染聊天框，也不将全部模块做成入口卡片墙。
- 页面有自己的标题、面包屑、筛选、操作区、列表/表单/设计器/详情和运行状态；支持独立 URL、刷新、返回和收藏。
- AI 对话与数据分析、报表大屏、知识中心、设备预警、质量检查等一样，是一个独立菜单模块。只在该模块中使用 Test5 的会话列表、对话区和交互式结果区。
- Test5 的产品入口归属“AI 工作台”，不作为系统名称、登录后首页或其他模块的父级界面。复用 Test5 的 Python 后端能力与采用 Test5 聊天界面作为全站布局是两件事；文件、知识、模型、权限与运行记录等公共能力仍由所属业务域统一管理，AI 模块引用同一资源，不另建一套。
- 分别设计常规业务页、可视化设计器和 AI 对话页：常规页保持标题/筛选/操作/内容的秩序；大屏、工作流、图谱编辑时可收起全局侧栏，按需展示组件或节点库、画布与属性面板；AI 对话页使用模块内部的会话与结果布局，不叠加第二套全站导航。
- 其他模块不强制出现聊天面板，也不要求把表单操作改成自然语言。可按实际价值提供“AI 生成”等按钮，但这些按钮不替代原有管理功能。
- 结果可以在 AI 模块直接预览，也可以打开完整业务页面；跳转只是选项，业务模块本身必须独立可用。
- 普通用户只看到被授权的模块；菜单不可见不构成安全边界，所有接口和数据访问仍由后端检查。

### 10.3 用户、组织与权限管理：独立页面和服务

| 子模块 | 独立页面及功能 |
| --- | --- |
| M22.1 用户管理 | 用户列表、搜索/分页、创建/编辑、启用/停用、成员归属、角色分配、密码重置、导入/导出及操作记录；敏感操作另行鉴权和确认 |
| M22.2 组织与部门 | 组织/工作区成员管理、部门树、上级关系、负责人、成员归属、部门状态；禁止越组织访问和非法循环归属 |
| M22.3 岗位管理 | 岗位列表、创建/编辑、成员关联、状态；岗位与角色分工明确，不默认岗位自动拥有全部业务权限 |
| M22.4 角色管理 | 角色列表、新增/编辑/复制/停用、分配用户、绑定功能与数据范围、预览有效权限和变更记录 |
| M22.5 菜单与功能权限 | 菜单树、页面入口、查看/新增/修改/删除/执行/复核/发布/分享/导出等操作授权，并关联真实后端权限标识和接口 |
| M22.6 数据与资源权限 | 本人/本部门/部门及下级/指定范围/本组织等数据范围，以及工作区、知识库、数据源、表字段、大屏、流程、设备、检测记录等资源授权 |
| M22.7 账号与会话安全 | 登录、个人资料、修改密码、密码策略、在线会话、会话撤销、异常登录与账号停用生效；限制锁死最后一个可用管理员的操作 |
| M22.8 系统设置 | 字典、系统参数、菜单配置等独立页面；敏感参数与凭据分离，配置变更可审计 |

权限必须同时覆盖：

1. 页面/菜单是否可见、路由是否可访问。
2. 按钮/业务动作是否允许执行，并在服务端强制检查，而不是仅隐藏按钮。
3. 接口和后台任务能访问哪些组织、工作区及具体资源。
4. 数据库查询、聚合、导出和检索中可访问的记录与字段；敏感字段脱敏，不能把不允许查看的财务或设备信息交给模型再隐藏显示。
5. 查看、编辑、执行、复核、发布、分享、下载、生产写回等不同授权；拥有查看权限不自动拥有发布或写入权限。
6. AI 可调用的能力范围和执行身份。实际权限取当前用户、资源授权和执行策略的交集，不能通过换说法、转用 AI 或工作流绕过限制。

所有入口默认拒绝未授权访问，权限在模型读取数据前和最终业务执行时检查；权限变更、账号停用和会话撤销后，已有会话与任务按明确策略复核或终止。列表、详情、文件下载、图表钻取、后台 worker 和直接 API 调用都遵守同样边界。管理页面允许检查有效权限并定位授权来源，不靠反复登录猜测权限。

可提供平台管理员、组织管理员、分析人员、设备运维、质检人员、只读查看者等初始角色模板，最终按组织职责配置，不把示例角色硬编码成唯一规则。用户与权限管理在 P1 交付，不能拖到所有业务模块完成后再补。

### 10.4 页面公共可用性要求

- 列表、表单、详情、画布、运行过程采用一致的页面结构和操作文案，提供加载、空数据、无权限、未配置、失败、成功等真实状态。
- 创建/编辑有字段解释、必要默认值说明、校验反馈、草稿保护和明确保存结果；模板选择不使用固定默认模板或首项兜底。
- 长任务显示状态、进度和可用的取消/重试；离开页面后可以从任务/结果列表继续查看。
- 删除、公开分享、生产写入和权限变更等动作显示影响范围，按权限与风险要求确认；不能把业务确认变成引入 Lynx 客户审批模块。
- 独立路由直接访问、浏览器刷新、返回、权限变化、分页筛选恢复和失败重试均纳入验收，排查菜单存在但页面缺失、组件空壳、按钮无事件等问题。
- 适配本机常用窗口大小与缩放、中文字体、键盘操作、表单焦点和上传/预览/导出，不将宽屏大屏展示布局套到所有管理表单。

### 10.5 前端组件职责

| 组件组 | 职责 |
| --- | --- |
| AppShell / ModuleNavigation / ModuleRouter | 全站普通业务布局、首页、顶部业务域导航、仅当前域的二级菜单、页面标签、模块路由与面包屑；不包含聊天状态或强制聊天区 |
| BusinessList / BusinessForm / BusinessDetail | 公共列表、表单与详情模式，保持各业务独有的字段和交互 |
| UserManagement / RoleManagement / PermissionEditor | 用户、角色、功能与数据授权、有效权限检查；后端仍执行实际鉴权 |
| ConversationShell / MessageParts | 仅用于 AI 对话模块的会话、流式消息、输入和安全确认卡片 |
| RunProgress / RunInspector | 模块页面及 AI 模块共用的任务状态、失败点、取消/重试与审计摘要 |
| ResourceResolutionCard | AI 模块解释使用的数据、口径和资料；必要时补充选择 |
| ResultHost | AI 结果或业务预览场景中，根据受校验的结果类型与资源版本加载相应组件，不充当全站路由 |
| DashboardWorkbench | 独立报表设计页面；组合 Lynx 画布、图层、属性、模板、提示词、数据绑定与钻取，渲染部分可复用到 AI 结果区 |
| GraphWorkbench | 独立图谱管理/探索页面；图谱浏览、实体关系和来源组件可复用 |
| AlertWorkbench / QualityWorkbench | 预警和质检的列表、表单、执行、结果与复核页面；结果组件供 AI 模块复用 |
| ArtifactViewer | Test5 文档/PPT/表格/PDF 预览、下载和继续使用，既可独立打开也可在 AI 结果中显示 |

这些名称是规划组件名，尚未新增源文件。实际模块目录按业务域组织，不能把所有页面代码堆入聊天页。

`ResultHost` 输入结果类型、资源 ID、资源版本、运行 ID 和授权操作；子组件通过明确事件提交编辑请求。图表数据、布局状态和对话上下文分开管理；视图不直接修改父级状态。手动修改和 AI 修改通过同一后端接口并使用版本检查，避免覆盖彼此的编辑。

### 10.6 AI 模块中的交互式结果类型

至少包括 dashboard、analysis_report、table、chart、knowledge_graph、workflow、alert_problem_list、quality_inspection、document、presentation、spreadsheet、pdf、configuration_draft。

所有结果关联真实资源、状态、版本、来源与可执行操作。图表钻取、筛选、刷新和对话修改使用同一资源上下文；历史对话重新打开时能恢复结果。业务模块可不经聊天记录直接读取、编辑和管理这些资源，不能依赖一次性页面内存。

## 11. 新数据库设计方向

另建统一业务数据库，开发/测试数据与当前业务库隔离，使用版本化迁移管理。以下为实体分组草案，不是最终 DDL：

| 数据域 | 核心实体 |
| --- | --- |
| 组织与权限 | organizations、workspaces、departments、positions、users、members、user_roles、role_permissions、roles、permissions、menus、data_policies、resource_grants、sessions、permission_change_logs |
| 对话与执行 | conversations、messages、runs、run_steps、tool_calls、run_events、resource_snapshots、confirmations |
| 资源与语义 | assets、datasources、dataset_metadata、field_metadata、business_terms、metric_definitions、relation_definitions |
| 能力与接口 | capabilities、capability_versions、api_operations、operation_versions、tool_bindings、capability_tests |
| 文件与知识 | files、knowledge_bases、documents、chunks、retrieval_config、recall_tests、sync_jobs |
| 本体与抽取 | ontologies、concepts、attributes、relation_types、mappings、extraction_jobs、extraction_results |
| 图谱 | 图谱目录、实体/关系来源与版本元数据；实体关系存储使用选定图数据库适配 |
| Bot 与工作流 | bots、bot_versions、workflows、workflow_versions、node_specs、bindings、schedules |
| 分析与大屏 | analysis_sessions、query_history、analysis_reports、insights、dashboards、dashboard_versions、widgets、data_bindings |
| 模板与提示词 | templates、template_versions、template_assets、prompt_categories、prompts、prompt_versions、usage_records |
| 设备与预警 | devices、measurement_points、expert_advice、collection_configs、alert_rules、alert_runs、problems、writeback_records |
| 质量检查 | quality_metrics、quality_templates、template_metric_bindings、inspections、defects、component_measurements、review_records |
| 应用与工件 | applications、application_versions、solutions、solution_bindings、artifacts、artifact_lineage |
| 系统与运营 | model_profiles、secret_references、audit_logs、notifications、operation_metrics、settings、job_logs |

约束：

- 模板、提示词、工作流和能力使用版本引用；运行记录固定所用版本。
- 工作区、所有权和资源权限在服务层统一执行，不只依赖前端隐藏。
- 财务与检测数值使用明确精度和单位；时间口径统一并保存原始时间信息。
- 文件由内容摘要和存储引用关联，不在多个模块重复保存不一致副本。
- 密钥只保存加密值和引用，不进入模型上下文、普通配置导出或日志。
- 新建演示数据必须标识为演示环境；无真实数据时不能自动拿演示库替代。
- 旧库保留。需要的模板、提示词、连接配置和历史资产可由独立幂等导入工具导入；不默认执行旧初始化 SQL 覆盖现有库。

| P2：分析与大屏完整模块 | 迁移 Lynx 分析页面、报表列表、完整设计器、全部组件、模板/提示词、保存/钻取/导出；同步建设语义目录、能力注册与 AI 模块的“财务与设备大屏”链路 | 用户可从正常页面完成分析和大屏制作，也能在 AI 模块生成和继续修改；同一资源互通，数字和组件逐项核验 |
| P3：Qknow 知识全链路 | 文件/知识库/RAG、概念关系、映射抽取、图谱、Bot/Chatflow 的完整模块页面与服务，同步注册可授权调用的 AI 能力 | 不进入聊天也能完成资料到知识/图谱/助手的配置与管理；AI 模块可协同操作，结果一致 |
| P4：共享工作流与工业业务 | 工作流列表/画布/运行详情、通用与业务节点、预警/测点/经验、质检设备/指标/模板、问题/复核/报告页面及真实服务联调 | 正常界面完整建流程、配规则、做质检；AI 模块可复用同一流程和业务能力；未配置状态不伪造成功 |
| P5：应用、运营与其余模块补齐 | 应用/解决方案、知识资产/Bot/应用运营、工具/技能/插件、文档/PPT 独立页面和能力保全，完善模型/消息/调度/监控及附属工具；接口合集同步 | 全量功能与页面清单闭合；运营数据真实；P1 的用户权限基础不是到此阶段才开始建设 |
| P6：全模块协同与完整发布验收 | 正常页面全功能、独立 AI 模块跨业务执行、接口/组件/数据/权限/异常/本机测试，文档合集、备份恢复与部署检查 | 正常操作和 AI 协同两套用例分别通过；所有功能有证据；未联调外部项不能标为通过 |

P2 是优先交付的完整业务模块，不代表其余模块被降为可删除项。每阶段同步交付正常模块页面、业务 API、权限、可供 AI 使用的能力契约、文档和测试；最终通过 AI 模块的跨业务贯通验收。不能以聊天演示成功代替模块完成，也不能为等待 AI 编排而推迟正常页面交付。

本机以 Windows 和现有 Test5 环境为主要基线，统一启动/停止/状态/环境检查入口。后台 worker、超时取消、中文路径、依赖服务、字体、图像/文档预览和导出均需实测；应用 Java 服务在 Python 对应能力验收后退出依赖链。

工期在 P0 得到接口/组件缺口、外部服务条件和真实验收数量后估算，不以简单页面数量承诺全量完成时间。

## 13. 验收：完整界面、用户权限、业务功能与 AI 协同分别通过

### 13.1 功能追踪格式

`功能编号 → 来源证据 → 新模块 → 菜单/独立路由/页面操作 → 业务接口 operationId → 权限/数据范围 → 数据依赖 → AI capability_id 或受限管理标记 → 页面/AI/API 测试编号 → 证据与结论`

范围内接口和 UI 操作均登记；受限管理项可以要求确认或管理员权限，但不能因不适合普通用户而无记录地遗漏。模块页面、接口业务正确性和 AI 协同是分开的验收维度，不互相代替。

### 13.2 正常模块页面必测链路

1. 登录后进入普通首页，按权限显示菜单；直接打开、刷新和收藏各模块路由均能进入真实页面，不要求存在聊天记录。
2. 管理员通过页面创建用户、维护部门/岗位、分配角色和数据范围；用户登录后有效权限与配置一致。
3. 角色调整、账号停用、会话撤销后，页面、直接 API、文件下载和任务执行按约定生效，不能继续使用旧权限访问。
4. 从数据源页面新增/编辑连接、测试、查看字段和同步元数据；从分析页面运行查询、查看结果/洞察/历史、质量检查和导出。
5. 从报表页面新建大屏，选择模板或无模板，编辑组件、数据绑定、主题和联动，保存、刷新、钻取与全屏；不先进入 AI 对话。
6. 从知识模块完成分类、文件上传、文档分段、召回测试、概念关系、映射抽取、图谱编辑和发布。
7. 从 Bot/工具/工作流页面配置能力、编辑画布、校验、调试、发布、查看版本与节点结果；预警和质检复用已建流程。
8. 从设备预警页面完成单条/批量请求体配置、选字段、JSONPath 预览、所有约定运算、目标表字段映射、试运行、问题处理和报告查看。
9. 从质检页面维护设备、模板和指标，提交图像/成分检测，检查逐项判定、缺陷明细、人工复核及报告追溯。
10. 从文档/PPT、模板/提示词、应用/解决方案、运营和系统运维各自页面完成实际操作；列表状态、记录与导出文件正确。
11. 验证普通用户、只读用户和管理员的菜单、按钮、接口、数据范围、敏感字段与 AI 能力边界，包含跨用户/跨工作区请求和未授权导出。
12. 聊天服务不可用时，用户管理、普通配置、已保存资源查询和其他非 AI 基础操作仍能正常使用；依赖模型的功能显示真实不可用状态。

### 13.3 独立 AI 模块必测链路

1. 进入 AI 模块，仅输入“生成财务和设备数字大屏”，自动定位已接入测试数据并展示真实可交互大屏；在报表模块也能查到并打开同一草稿。
2. 连续说“看近三个月”“改成明亮模板”“增加异常设备排行”，保持同一任务上下文和正确版本。
3. 说“复用制造业提示词”“保存刚才提示词”，分类、内容和引用记录正确。
4. 说“把结果做成 12 页 PPT”，保留 Test5 的页数、内容和模板能力，验证实际导出文件。
5. 说“上传资料建知识库并抽取设备关系”，最终可检索、有引用、可展示真实图谱。
6. 说“建立温度超限预警，按目标字段生成问题报告”，验证单条/批量、JSONPath、运算、集合、写回权限和防重复。
7. 说“按新质检模板检查这批图像和成分数据”，验证逐项判定、复核和报告来源。
8. 说“查看失败任务、运营统计、模型状态”，显示真实记录，不能读取静态演示看板当作线上状态。
9. 用非管理员提出越权、生产写入、删除、公开发布等请求，验证权限和必要确认。
10. 无数据、无授权、接口未配置、参数歧义、模型/检测服务超时，返回可解释状态且不产生伪造成功记录。

### 13.4 自动化门槛

- 参数校验、权限与资源隔离、规则运算、空值/除零、时间/单位、SQL 限制等有确定性测试。
- 前后端接口合同测试包含业务码、响应内容、状态变化和持久化；不能只断言 HTTP 200。
- 页面刷新/直达、历史结果恢复、所有有效按钮、上传/下载、模板/提示词、画布编辑和钻取有浏览器测试。
- 正常模块页面的用例不经 AI 对话跳转或构造聊天记录才能执行；AI 模块另有对话生成、资源互通和连续修改测试。
- 用户、部门、角色、菜单/动作权限、数据范围、字段脱敏、会话撤销与后台任务权限复核有独立用例；只检查菜单隐藏不能通过。
- 大屏组件覆盖按目录逐项记录；所有 20 套大屏模板和 20 套 PPT 模板分别回归。
- 关键统计值与预先计算的测试答案一致，复杂联表验证粒度与聚合，不能用模型自己的解释作为唯一正确性证据。
- 模拟接口测试和真实外部模型/设备联调分开统计；“待配置”不是“功能验收通过”。
- 后台任务重启恢复、防重复执行、SSE 重连、取消和超时实测。
- 新建库安装、迁移版本检查、环境检查与备份恢复演练通过。
- 接口注释完整性、规范/合集可导入性、实际调用与 AI 注册对应关系检查通过。

## 14. 风险与实施前约束

- Qknow 部分前端功能需要补齐后端，这部分是新实现工作量，不是简单搬代码。
- Lynx 组件目录覆盖与真实渲染覆盖可能不同，逐组件测试是必要工作。
- 数据语义与口径需要管理员配置和业务确认，单靠接口注释不能保证跨财务/设备分析正确。
- 外观与成分检测需要真实服务、设备和样本；通用视觉模型可调用不等于工业检测质量达标。
- 现有 Test5 工具契约中的权限/确认字段必须落实为网关执行约束，不能只停留在描述字段。
- 对话自动化不赋予额外权限；初始接入、生产写入、公开分享、删除和权限修改按照独立授权规则执行。
- 正常系统外壳、独立模块页面和用户/权限管理是基础交付，不属于 AI 模块的附属界面，不能在实现时压缩成聊天卡片或仅管理员可用的配置入口。
- Qknow 本地 LICENSE 含品牌与署名附加条款；复用代码、前端和第三方引擎资产前核对授权并保留归属。不明授权二进制不直接带入新系统。
- 本文中的模块、接口分组、表名和组件名是目标设计草案；不代表已经实现、迁移或验证可用。
