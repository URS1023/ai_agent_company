# qKnow 功能与界面核查

核查日期：2026-10-20；作者：agent-1020-qknow；任务：T-agent-1020-qknow-01。

本轮实际枚举 `qKnow-develop/qknow-ui/src/views` 的 194 个 Vue/JS/TS 源文件，其中 190 个 Vue 文件；覆盖 11 个顶层功能域。完整路径、分组、用途、源码标记和验证状态见同目录 `qKnow_界面源码索引_20261020.csv`。该统计包含详情、弹窗、选择器及节点配置组件，不等于 194 个独立路由或已完成业务功能。没有启动服务、调用数据库或在线演示。

## 结论与最新需求适配

qKnow 应保留为新版的整体视觉、信息架构、业务模块和图谱增强功能来源。知识库、Bot、工具、模型等能力与 Dify、Open WebUI 重叠时，保留 qKnow 入口和业务组织思路，具体执行能力以用户已指定的两套内核为准。qKnow 原来的未完成页面仍是明确的需求候选，不能从需求清单中删除，也不能把它们标记为已经实现。

当前 qKnow 的工作流画布、看板与应用卡片的表现，明显超出实际后端完成范围。建议按页面逐项登记“外观要保留、功能要实现、执行由谁负责”，避免继续为 qKnow 自建工作流补全内核，与已明确复用的 Dify 重复。

## 影响实施建议的明确缺口

1. **工作流菜单大于执行能力。** `qknow-ui/src/views/kb/bot/build/index.vue:1190` 的 `ENABLED_ADDABLE_NODE_TYPES` 只启用 `llm`、`reply`。同文件约1195—1261行还展示条件分支、循环、HTTP、文档提取、参数提取、代码执行、迭代、知识检索和问题分类；约4828行禁用类型弹出“正在开发中”。后端 `qknow-module-kb/.../service/flow/factory/NodeFactory.java:63` 的 switch 只构建 START、LLM、REPLY，其他类型进入不支持分支。这支持直接复用 Dify 节点和运行体系。
2. **已有流程保存/调试/执行入口。** `KbFlowController.java:48` 起有 `/kb/flow`，63行保存，71行测试SSE，81行执行，92行流式执行，118行Chatflow测试。它们说明旧项目有真实实现痕迹，不能因部分节点未实现而否认全部功能，也不能据此认定Dify等价能力已经齐备。
3. **三张运营看板缺真实接口。** `views/kd/knowledgeAsset/index.vue:546`、`botOperation/index.vue:434`、`appOperations/index.vue:500` 明确留有后端接口就绪后接入的TODO；知识资产页面实际 `fetchKnowledgeAssetDashboard()` 返回空结构，并在演示模式使用示例数据。
4. **应用和插件有演示/预留行为。** `views/kac/overview/index.vue:121` 与122行注释掉真实API导入，136/222行定义静态方案和应用列表；`plugin/index.vue:425` 有 `mockPluginList`。`horizontal/components/card.vue:397` 等多处、`mySolution/components/solutionCard.vue:328` 显示开发中。API文件存在不能替代后端契约与发布绑定功能。
5. **测点/告警/建议存在前端而后端覆盖不足。** `api/dm/dmMeasurePoint/point.js:24`、`dmAlarmConfig/config.js:24`、`dmExpertAdvice/advice.js:24` 定义对应路径；本次枚举的本地dm模块Controller仅数据源。需后续全局路由/依赖及实际启动环境核实，当前应标“待补链路/未验证”。
6. **本地未发现独立产品质检、设备质检、报表设计器页面域。** 当前views域没有qc/report；设备侧主要为测点、告警和专家建议。质检/报表需求来自用户业务及其他项目资产，不能据qKnow菜单推断它已具备。

## 技术复用边界

`qknow-ui/package.json:71` 明确 Vue 3.4.31，Element Plus 2.7.6（52行）、Pinia 2.1.7（66行）、Vue Router 4.4.0（75行）、Vite 5.3.2（92行）；另有 G6、X6、Vue Flow、ECharts、Monaco。后端为 JDK17/Spring Boot 3 模块化项目（README约100行）。

若保留Vue独立模块，可原生复用 qKnow 布局/图谱/抽取等组件；若统一为另外两套项目的前端栈，则应移植设计令牌、页面结构和交互规则。三个项目的组件与运行状态不能直接拼成一个页面。建议先用统一登录、导航、资源标识与模块路由组织独立应用，再按产品需要逐步合并；这是本轮架构建议，尚未替用户冻结部署方式。

本地 `qKnow-develop/LICENSE:3` 起为 Apache 2.0 加qKnow条件，9/11行写明商业使用中的标志/归属保留与另外授权要求，而 `qknow-ui/package.json:6` 写MIT。直接复用前须按项目实际文件核对这处差异；本条是本地文件事实记录，不作法律结论。
